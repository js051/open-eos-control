# Ordinary shooting-setting outcomes v1

Applies to existing advertised setting transports only. A complete successful transport response is not an exact camera ACK or proof that a write caused a later value. Unknown write evidence never upgrades from a later matching GET.

POST /v1/session/{id}/settings/{key}/outcome with {"value":"..."} returns HTTP 200 and version, actual engine, exact key, exact requestedValue, writeEvidence="response-received", readbackEvidence="matched"|"mismatch"|"unavailable", and setting (null for unavailable). A read failure after response does not erase response evidence. No fallback mutation to the legacy POST. Unsupported scoped providers fail before dispatch. The legacy POST remains compatible.

GET /v1/session/{id}/settings/{key} returns {version:1,engine,setting}. This is a fresh bounded scoped observation, never cached status/capabilities or a mutation. Full ordinary CameraSetting fields are key,label,value,values,inputKind,maxLength. Choice values are unique, 1..1024 strings; current must be advertised. Strings are valid Unicode without controls/surrogates, <=512 code points, keys match [a-z][a-z0-9._-]{0,63}; label <=512. Text requires empty choices, maxLength integer 1..255, and printable ASCII value within it; choice maxLength absent/null.

Parse a bounded complete JSON response first, rejecting duplicate keys, non-JSON constants, invalid UTF-8/surrogates, truncation and ambiguous framing. HTTP200 plus strictly matching base fields retains response evidence independently; invalid/missing/contradictory observation yields unavailable. Invalid base yields unknown. Request key/value/actual engine cannot be inferred from the response.

Freeze exact owner/session object, editor, requested string, revision, one writable route and attempt. Require transport-supported ability evidence and fresh prewrite full structured siblings, no mutation fallback or optimistic current cache. Canon USB event-derived ability is updated by a strict event drain, not claimed as a new complete descriptor when no ability event is delivered; fresh exact property readback remains separately required. Preserve transport prerequisites and safety gates. At most 20 retained attempts; manual recovery only does bounded reads for a retained same-owner attempt. Current publishing requires same attempt/owner and uncancelled invocation; draft consumption additionally requires same revision, response and matching fresh observation. Same-value user edits count as a new revision; passive render does not. Events may update observed values/abilities but must not replace selected intent or upgrade write evidence. Cancel/reconnect never automatically replay.

Fixtures exercise policy; they do not prove native compilation, network pipelines, camera ACK contracts, real-camera or performance behavior.
