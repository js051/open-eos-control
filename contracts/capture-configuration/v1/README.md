# Capture configuration evidence contract v1

Scope: existing capture-directory creation and seven-field Canon naming workflows only. No new transport, writes during recovery, or inferred physical-camera guarantee.

writeEvidence: not-sent only before this logical write dispatch; unknown after dispatch without a validated same-attempt ACK; acknowledged after that ACK even if later refresh/cancellation fails. Invalid ACK before dispatch is ignored. readbackEvidence is independent: not-read, unavailable, directory refreshed, naming matched/mismatch. A matching later read never proves an unknown earlier write succeeded. Directory ACK is only a returned five-character suffix and does not identify an exact numbered folder or selected card.

Bridge post-ACK readback failure remains HTTP502 with error code CAPTURE_CONFIG_READBACK_FAILED, engine ccapi and operation-specific feature DIRECTORY_CONTROL/FILE_NAMING_CONTROL. Optional error.captureConfigReceipt has exact version1, operation create-directory/set-file-naming, stage acknowledged, requestedValue and acknowledgedValue. Directory field must be absent; naming field must exactly match the frozen field. Requested value must match the frozen request byte-for-byte. Directory ACK must be five ASCII uppercase letters/digits/underscore; it may differ and must then be displayed accurately. Naming ACK must equal the requested value. No receipt is issued for pre-write failure, malformed ACK or another error. Success payloads remain compatible. Strict endpoint, ability, current-range and complete seven-resource validation stay required.

Each frozen action has an original session object/generation, immutable target/request and draft revision. Late proof may settle its existing bounded record but never repopulate removed records or affect a replacement owner. Current UI publication needs exact owner/attempt and not retired. Draft consumption additionally needs matching draft revision, valid ACK, matching readback and not cancelled. Independent user edits remain intact. Only explicit fresh bounded read recovery is allowed; zero mutation requests and no inferred operation success from observations. History is at most20 records per app session; no credentials, image data or URL userinfo/query/fragment are recorded.

Cases are shared pure policy fixtures. Passing them does not replace product UI, native compilation, real HTTP framing/cancellation, or physical-device acceptance.

The additional exact-value-vectors.json pins 88 strict ASCII/full-string cases (68 receipts, 13 complete naming groups, 7 directory selections). Terminal LF/CRLF, non-ASCII lookalikes, leading zeros and unsupported forms fail closed. Original 241 policy cases remain unchanged.

Bridge recovery performs one canonical directory GET or seven naming GETs, never generic capabilities/cache fallback. Its 15-second budget includes lock acquisition, checks before/after each request and between bounded response body chunks. urllib DNS/initial response headers and a blocking socket read are not forcibly cancellable; late observations are rejected. This is cooperative budget enforcement, not a guaranteed hard server-side cancellation deadline.
