# Recording lifecycle v1

One admitted Start or Stop write, never automatic replay. Camera command response and fresh recording observation are separate evidence. A complete validated Stop response resolves command duty and permits a deliberate new Start; it does not establish physical recording=false. A rejected/lost/truncated Stop retains prior duty. A genuine fresh false observation may resolve duty independently. Unknown Start establishes Stop duty. Cached CameraStatus.recording never resolves duty or admits stopped-video review.

GET /v1/session/{id}/recording/observation returns {version:1,engine,observationEvidence,recording,source}. observationEvidence is observed/unavailable/read-failed. Only observed carries exact boolean and a source from ccapi-event,ccapi-simulator,usb-evf-record-status,gphoto-config; otherwise both null. POST /v1/session/{id}/recording/{start|stop}/outcome returns {version:1,engine,operation,responseEvidence,observation}; responseEvidence is response-received/not-sent/unconfirmed/rejected. Direct canonical CCAPI ACK accepts complete empty200 or unique empty JSON object200, or empty204; other status/shape is not ACK. Simulator contracts are explicit and separate. Both Bridge routes require exact HTTP200, exact envelope keys, bounded complete unique-key JSON, no redirect or command replay. New Bridge command routes retain rejection headers400/401/403/404/405/409/410/422/429 even if the diagnostic body is unavailable;408 and5xx remain unconfirmed. Native Canon response rejection is a separate transport contract. Original response evidence is immutable; recovery is one separate read. not-sent means no REC write was admitted, including a known preflight failure or true existing no-op; it is never ACK. Only a fresh observed target can make a no-op useful state evidence.

Real CCAPI does not currently expose a verified dedicated recording GET in this implementation. Its assignment cache is not observation. Canonical queued CCAPI events are change hints, not a verified fresh-state reader: receipt time or local sequence cannot prove when the camera produced an event. The ccapi-event source is reserved for an explicitly proven provider contract, and synthetic fixtures cannot enable it in production. No invented endpoint or inference from movie mode, thermal state or filename. gPhoto config requires exact fresh Card/None read and must not silently stop another transport. USB requires the existing advertised REQUEST_DEVICE_PROP_VALUE read for EVF_RECORD_STATUS, with the request-scoped queue/read boundary; merely draining queued events or reading an old property cache is unavailable.

Sources are bound to engine: ccapi-event/ccapi-simulator require ccapi; gphoto-config requires libgphoto2; usb-evf-record-status requires usb-ptp. Cancellation suppresses publication, never drops admitted Start safety duty, including cancelled/retired records. Old-owner duties remain previous-connection warnings and never attach to a replacement. Publish requires same connection and same attempt, not cancelled or retired. Keep at most20 sanitized in-memory attempt records; previous connections cannot mutate current state or replay their commands. Stop-review requires a current owned fresh false, never response alone. Existing media-selection flow owns candidates and no command is replayed to find a clip. Native/physical validation remains a separate evidence tier.
