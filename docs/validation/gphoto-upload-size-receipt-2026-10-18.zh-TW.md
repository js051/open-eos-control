# gPhoto2 上傳精確位元組回執

日期：2026-10-18。狀態：本機實作與合成回歸驗證；沒有實機驗收。

## 官方契約與缺口

- 固定來源為 gphoto/gphoto2 commit `70e83ed3fd630c656e7859f2a510b70bc20b50b8`，`gphoto2/actions.c` blob `b82c070b0c43df474b8a48d29c763a5d60c20074`。本次以 GitHub 檔案介面讀取固定 commit，並非只引用可變的 master。
- [`print_file_action` 普通清單輸出](https://github.com/gphoto/gphoto2/blob/70e83ed3fd630c656e7859f2a510b70bc20b50b8/gphoto2/actions.c#L390-L410)將大小向上取整成 KB，因此清單中的 2 KB 不能作為 1025、1026 或 2048 位元組的精確回執。
- [`print_info_action`](https://github.com/gphoto/gphoto2/blob/70e83ed3fd630c656e7859f2a510b70bc20b50b8/gphoto2/actions.c#L272-L344)使用指定資料夾與檔名讀取檔案資訊，固定回顯同一對身分，再依序輸出 File、Thumbnail、Audio data。只有主檔案具備大小旗標時，File 區段才輸出原始整數位元組大小。

## 修正界線

1. 保留上傳前後的嚴格資料夾清單及唯一目標身分檢查。
2. 以該次清單實際找到的同一 ID，透過既有媒體資訊路徑執行一次唯讀 `--folder … --show-info …`。
3. 僅上傳回執要求嚴格 UTF-8、精確回顯檔名／資料夾、唯一且順序正確的三個區段、唯一已知主檔案欄位，以及恰好一個 unsigned 64-bit 範圍內的整數 `byte(s)` 大小。缺少或歧義資訊不能使用清單、縮圖、音訊或要求的長度補值。
4. 精確大小相等後才觀察到 MEDIA_UPLOAD 成功並傳回回執；任何一位元組差異仍失敗。一般媒體資訊 API 保留原有寬容顯示行為。
5. 保留已提交上傳之後完成讀回的取消語意。沒有新增重送、下載、刪除、大小容許區間、相機寫入或任意原始命令。
