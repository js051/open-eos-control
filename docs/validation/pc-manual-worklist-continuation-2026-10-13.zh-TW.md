# PC 未完成工作清單的明確接續

本批接續既有 P2 交付流程，基於原 PC 開發候選。舊版只保存已選清單及嘗試結果；本批新增使用者主動選取未完成列、逐列指定目前已載入素材、確認未知結果，再選擇新資料夾開始新嘗試。名稱僅供顯示，絕不以檔名、大小、相機網址或重用 ID 自動配對來源。

## 使用流程與結果語意

- 開啟批次歷史，為需要接續的列選擇當前連線已載入的原始素材。未選的列保持不動，已完成的關聯家族不能再由祖先入口接續。
- 同一原檔、同一關聯家族不能在這次選擇中重複綁定。任何排隊或未知列都可能仍由另一分頁的批次接續執行；每次接續均須先檢查目的地與其他分頁並明確確認，不只已知未知結果。
- 點擊開始會在同一使用者操作中提出新的資料夾選擇。只使用支援 File System Access 的瀏覽器；不支援時保留原有單檔下載，不能把 anchor 觸發當成批次已儲存。
- 選擇資料夾後，先原子保存新的完整關聯清單，之後每列先保存開始嘗試，再開啟目的檔及 GET 原檔。接續的 admission 失敗一律停止，不沿用一般手動下載的未記錄相容路徑。
- 新嘗試使用既有名稱碰撞檢查及新批次子資料夾 adapter；瀏覽器沒有原子 exclusive-create 保證，因此不能排除外部寫入者在檢查與建立之間造成競爭。確認 writer.close 才記完成，不宣稱硬體 fsync 或檔案未來仍存在。舊結果保留；較晚的原嘗試完成只更新其自己的 receipt。
- Stop、斷線或換連線會退休目前執行權。清除會退休選擇草稿及歷史 epoch，阻止後續接續列准入；它不停止已開始的檔案 I/O，該 writer 仍可能完成 close，舊 receipt 的晚到結果不會重建已清除紀錄。相同 wire session ID 不代表同一連線。離線僅查看歷史，不偷偷重連或 GET。

## 持久資料與相容性

Snapshot v3 可讀 v1/v2，在成功寫入的同一 IndexedDB transaction 遷移。只新增隨機本地 batchId/rowId 關聯；不保存 media ID、session ID、URI、目錄 handle、路徑、授權或確認選項。舊版客戶端拒絕未知新 schema，不能覆寫 v3。

100 列及 100 KiB 原上限保持。新接續須容納完整選定 roster，不能淘汰舊證據或截短新選擇。50 列中 5 已完成、1 未知、44 排隊的冷讀可明選後 45 列建立新 roster，總計 95 列。已滿時明確拒絕，使用者可另處理歷史紀錄；不自動清除。

關聯只是使用者選擇的本地關係，不是相機來源同一性的證明。整個祖先／後續家族的完成、目前 active、未知或殘留風險都參與准入判斷，不能挑舊祖先隱藏新結果。另一分頁可能繼續原嘗試，人工確認不能保證它已停止。

## 驗證界線

新增 store 與真 production caller 控制涵蓋：新關聯結果、50 列冷讀、容量拒絕、v2 遷移、非法／循環 link、祖先與後續結果、明確素材及未知確認、目的地選擇、durable admission、clear 失敗不降級、取消／同 ID 換連線、不重複原檔 GET。

本地 Node 控制以合成 IndexedDB／目的地／HTTP回覆驗證程式行為，不能代替原生瀏覽器權限提示、真相機及實際儲存裝置驗收。完整瀏覽器及跨平台整合 runtime 尚待本批正常 CI／集中驗收，未宣稱產品全部完成。

本地完整 29 個 Node 模組於本候選通過，含 743 個 node:test case 及既有直接 assertion scripts。新增雙語 browser 旅程走真 DOM／Bridge／原檔 bytes，但目的地 writer 為既有合成介面；此兩旅程僅完成語法檢查，runtime 尚未執行。
