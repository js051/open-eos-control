# Capture destination and naming outcomes

The existing CCAPI directory-create and seven-field file-naming paths now preserve a validated same-attempt write acknowledgment if their follow-on read fails. The bridge returns HTTP 502 CAPTURE_CONFIG_READBACK_FAILED with a bounded typed receipt only for this post-ACK state. A lost/malformed response remains unknown; a later matching observation never upgrades unknown write evidence.

The desktop keeps up to 20 frozen records, including original session object/generation, exact request, acknowledged suffix/value and draft revision. A cancelled or replaced invocation can settle its retained history but cannot update current controls, consume a newer draft or release another invocation's lock. Input events, including same-value re-edits, are new drafts; render synchronization is not. Reusing a consumed draft requires an explicit new-request action. Old history cannot overwrite a newer write summary.

After a valid successful directory ACK, one scoped fresh read updates the picker; a failed follow-on read retains the ACK and offers explicit recovery. A typed HTTP502 ACK failure does not automatically retry its read. Explicit read-only recovery uses one canonical directory-selection GET or all seven exact naming GETs. Generic capabilities and aggregate settings are not substitutes. Complete current values and abilities are validated before updating controls. Directory ACK is only a five-character suffix and does not prove the exact numbered folder or card. A failed recovery hides stale observations. A successful recovery after cancellation may publish fresh values while retaining the original cancellation and write uncertainty.

Configuration HTTP responses are limited to 64 KiB, complete UTF-8/JSON, unambiguous framing, unique keys and exact ASCII value forms. Configuration redirects are disabled. The desktop sends one logical mutation request and never retries automatically. This cannot prove a physical camera executed exactly once.

Bridge recovery's 15-second budget includes bounded lock acquisition, checks before/after each GET and between bounded body chunks. urllib DNS/header setup and an individual blocked socket read cannot be force-cancelled; late observations are rejected. The browser has separate 30-second write and 15-second recovery cancellation timers. These are not a hard server-side cancellation guarantee.

Validation fixtures include 241 shared policy cases and 88 exact-value cases, actual Python CcapiSession/FastAPI tests, Node tests extracting production owner functions, and ten authored production-page browser journeys. Browser execution remains pending in this environment; native/physical camera checks are separate. No real camera or user-file mutation is performed by the synthetic tests.
