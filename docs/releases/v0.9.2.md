# Open EOS Control v0.9.2 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

`0.9.2` 修正 Android 既有拍攝資訊在旋轉與大字體下的顯示，因此採 patch 版號。仍是 Development Preview，不是穩定版，也不代表機身手動拍攝失焦已解決。

### Android 變更

- 修正 Photo/Video、FPS、AF、放大倍率及 REC/Bulb 標籤的裁切。繪製前依實際可用空間，以一致的字體與行高量測，不再逐幀縮字；保留固定觸控位置及模式的完整文字。
- 白平衡與記憶卡就緒狀態使用英／繁中簡短標籤，完整名稱仍可透過無障礙描述、設定選擇器與詳細資訊讀取。曝光格明確分配標籤與值的空間。
- ISO、Tv、Av、剩餘張數和時間不從數字中間斷行，例如 `2:00:00` 不再拆為兩行。放大倍率的圖示與數值上下排列，不互相覆蓋。
- 相機命令、AF 釋放恢復、連線與系統旋轉政策不變；這不是變更相機 AF 模式或修復光學失焦。

### 驗證與限制

- 功能 [PR #190](https://github.com/js051/open-eos-control/pull/190) 通過 exact-head [CI](https://github.com/js051/open-eos-control/actions/runs/34043328118) 與 [main acceptance](https://github.com/js051/open-eos-control/actions/runs/34044412738)，包括 Android unit/build 與 API 34／36 UI 測試。
- 本地 Android 507 項單元測試、lint、App／測試 APK 建包通過。HTC U24 Pro／API 34 的 114 項畫面與 21 項對焦流程回歸通過，共 135 項，不重複計數；使用隔離 `.debug` App、離線 fixtures／本機 MockWebServer，不是相機實拍。
- 顯示矩陣涵蓋 360×800、800×360、800×1280，四方向、英文／繁中、1／1.5／2 倍字體與五種狀態，共 360 個組合；另驗證 168 個白平衡組合。檢查實際文字排版、可見邊界、數字不斷行，以及固定且至少 48 dp 的主要觸控區，並檢查截圖。
- **沒有向實體 R6 Mark III 發送 AF、半按或拍攝命令作本輪驗證。** 操作者暫時無法比較機身半按，失焦原因、實拍銳利度與弱網行為仍待確認。既有 AF-ON 必須先放開才能按 App 快門；程序強殺或斷網仍可能阻止停止送達。
- 未知的超長相機名稱／設定值和超出矩陣的字體比例仍可能使用明確省略號，保留詳細資訊入口。這不是全 App 排版完成宣稱。
- 本輪產品行為只修改 **Android**；PC／iOS 只對齊版本，未同步 Android UI。Camera Import 維持 artifact `1.1.0`／wire `1.0`，不修改 Serein 契約。

完整依據：[Android 拍攝資訊旋轉與大字體顯示](../validation/android-hud-text-layout-2026-09-06.zh-TW.md)。

### 安裝與發行檔

- Android：`open-eos-control-android-0.9.2-debug.apk`，`versionCode=25`。沿用固定開發簽章及 Preview package，可更新同簽章舊 Preview，不覆蓋獨立 `.debug` 測試 App。
- PC：版本對齊的 Windows x64 Bridge executable、Python wheel 與 source distribution；沒有新增本版 Android UI 行為。

- 另附 Camera Import ZIP／Kotlin JAR、`BUILD-PROVENANCE.json` 與 `SHA256SUMS.txt`。專用 Actions workflow 發布 exact-main immutable candidate，不手動重建替換資產。

## English

`0.9.2` repairs existing rotated and large-font Android shooting information, warranting a patch version. It remains a Development Preview, not a stable release or proof that camera-body defocus is resolved.

### Android Changes

- Fixed clipping in Photo/Video, FPS, AF, magnification, and REC/Bulb labels. Text is measured before drawing against actual space with matching font and line-height rules, without shrinking over successive frames. Control positions and complete mode labels remain fixed.
- Compact English/Traditional Chinese white-balance and card-ready labels retain full names in accessibility descriptions, pickers, and details. Exposure cells allocate explicit space to labels and values.
- ISO, Tv, Av, remaining-shot counts, and time values do not split numeric tokens across lines: `2:00:00` stays intact. Magnification icons and values are vertically separated instead of overlapping.
- Camera commands, AF release recovery, connection behavior, and system rotation policy are unchanged. This does not change camera AF modes or repair optical defocus.

### Evidence And Limitations

- Feature [PR #190](https://github.com/js051/open-eos-control/pull/190) passed exact-head [CI](https://github.com/js051/open-eos-control/actions/runs/34043328118) and [main acceptance](https://github.com/js051/open-eos-control/actions/runs/34044412738), including Android unit/build and API 34/36 UI tests.
- Local validation passed 507 Android unit tests, lint, and App/test APK builds. HTC U24 Pro/API 34 passed 114 screen and 21 focus-flow tests, 135 unique tests, in an isolated `.debug` App with offline fixtures/local MockWebServer rather than a physical camera.
- The layout matrix covers 360x800, 800x360, and 800x1280, four rotations, English/Traditional Chinese, 1/1.5/2 font scale, and five states: 360 combinations, plus 168 white-balance cases. Actual text layout, visible bounds, unsplit numbers, fixed touch targets of at least 48 dp, and screenshots were checked.
- **No physical R6 Mark III AF, half-press, or capture commands were sent for this validation.** Body half-press comparison, defocus cause, photograph sharpness, and weak-network behavior remain pending. AF-ON must still be released before the App shutter; process death or network loss can prevent stop delivery.
- Unknown long camera names/settings and font scales outside the matrix may still use explicit ellipsis with details available. This is not whole-App layout acceptance.
- Product behavior changes are **Android-only**. PC/iOS versions are aligned, without Android UI parity. Camera Import artifact `1.1.0` / wire `1.0` and the Serein contract are unchanged.

See [rotated and large-font HUD evidence](../validation/android-hud-text-layout-2026-09-06.zh-TW.md).

### Distribution

- `open-eos-control-android-0.9.2-debug.apk`, `versionCode=25`, retains the persistent development signer and Preview package for matching older Preview upgrades, separate from the isolated `.debug` test App.
- Version-aligned PC assets include the Windows x64 Bridge executable, wheel, and source distribution, without this Android UI change. iOS remains source plus Simulator CI, without an installable signed IPA.
- Camera Import ZIP/Kotlin JAR, provenance, and checksums accompany the release. The dedicated Actions workflow promotes the exact-main immutable candidate; assets are not manually rebuilt or substituted.
