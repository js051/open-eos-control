# Open EOS Control v0.1.8 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 第九個開發預覽版。此版本把 `v0.1.7` 後合併的 Android 相機式方向介面與 Android、iOS、PC Canon CCAPI RTP 相機音訊監看打包成可安裝、可驗證的版本。

### Android 相機操作介面

- 拍攝骨架固定在裝置自然顯示軸，轉動手機時不重排 Live View、快門、曝光列、模式列與設定面板外框。
- 相機名稱、電量、儲存空間、曝光值、FPS、模式文字與工具圖示在固定槽位內各自旋轉，不再把整條長文字塞進狹窄的側向工具列。
- 完整離線提示在側向時沿 Live View 長軸重新量測；Live View 設定等長內容則在固定面板內交換量測軸，從使用者視角呈現可捲動的寬版側邊面板，不刪除繁中或英文內容。
- App 讀取 Android 公開的 `ACCELEROMETER_ROTATION` 設定。系統自動旋轉關閉時，方向監聽器會停止、控制角度歸零；Quick Settings 變更、回到前景與新姿態事件都會重新核對。
- CI 保存英文直向、繁中 130% 字級側向、倒置及側向設定畫面。AVD 另以真實 Settings Provider 驗證旋轉鎖開關、監聽器生命週期與舊姿態清除。

### RTP 相機音訊

- Android、iOS 與 PC 都只在 Canon SDP 公告帶內 `MP4A-LATM/48000` 時開放音訊監看。
- 三個平台分別完成有界 RFC 6416 重組、AAC 解碼、預設靜音、前景或工作階段生命週期及獨立診斷；音訊失敗不會中止已可用的 Live View 影像。
- 這些路徑已有固定封包與平台測試，但仍需要 EOS R6 Mark III 的實際 RTP 音訊驗證。

### 下載

- `open-eos-control-android-0.1.8-debug.apk`：使用固定開發簽章的 Android 安裝包，可直接更新 `0.1.5` 以上預覽版。
- `open-eos-control-bridge-windows-x64-0.1.8.exe`：Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.1.8-py3-none-any.whl` 與 `.tar.gz`：Desktop Bridge Python 套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

### 已知限制

- 這是開發預覽簽章，不是正式商店簽章。
- 相機式方向行為已在 Pixel API 34 AVD 驗證；Pixel Android 16 實機仍應以本版本的診斷報告確認 `productVersion`、`systemAutoRotationEnabled` 與 `controlRotationDegrees`。
- 並非所有能力都已完成 EOS R6 Mark III 全功能實機回歸，控制仍依相機或 backend 公告開放。
- 此版本仍不提供已簽章 iOS IPA；Windows USB 控制仍需要系統可用的 `gphoto2`／libgphoto2。

## English

This is the ninth Open EOS Control development preview. It packages the Android camera-style orientation UI merged after `v0.1.7` together with Canon CCAPI RTP camera-audio monitoring on Android, iOS, and PC.

### Android Camera UI

- The capture skeleton stays on the device's natural display axis. Rotating the phone does not reflow Live View, the shutter, exposure rail, mode rail, or settings-panel frame.
- Camera name, battery, storage, exposure values, FPS, mode labels, and tool icons rotate independently inside fixed slots instead of forcing a long status row into a narrow sideways toolbar.
- Complete offline guidance remeasures along the Live View long axis. Reading-heavy surfaces such as Live View settings swap their internal measurement axes inside the fixed panel, producing a scrollable wide side panel from the user's viewpoint without dropping English or Traditional Chinese copy.
- The app reads Android's public `ACCELEROMETER_ROTATION` setting. When system auto-rotate is disabled, the orientation listener stops and control rotation returns to zero; Quick Settings changes, foreground return, and new posture samples all reconcile the policy.
- CI retains English portrait, Traditional Chinese 130%-font sideways, upside-down, and sideways-settings screenshots. AVD tests also exercise the real Settings Provider for rotation lock, listener lifecycle, and stale-posture clearing.

### RTP Camera Audio

- Android, iOS, and PC expose audio monitoring only when Canon's SDP advertises in-band `MP4A-LATM/48000`.
- Each platform implements bounded RFC 6416 reassembly, AAC decoding, default-muted playback, foreground or session lifecycle, and independent diagnostics. Audio failure cannot stop an otherwise ready Live View video session.
- Deterministic packet and platform tests cover these paths, but physical EOS R6 Mark III RTP audio validation remains pending.

### Downloads

- `open-eos-control-android-0.1.8-debug.apk`: Android package using the stable development signer; it can update previews from `0.1.5` onward in place.
- `open-eos-control-bridge-windows-x64-0.1.8.exe`: single-file Windows x64 Desktop Bridge.
- `open_eos_control_bridge-0.1.8-py3-none-any.whl` and `.tar.gz`: Desktop Bridge Python packages.
- `SHA256SUMS.txt`: SHA-256 checksums for every attached file.

### Known Limitations

- This is a development-preview signing identity, not a production app-store identity.
- Camera-style orientation is verified on a Pixel API 34 AVD. Pixel Android 16 hardware should still confirm `productVersion`, `systemAutoRotationEnabled`, and `controlRotationDegrees` in this build's diagnostic report.
- Not every capability has completed a full EOS R6 Mark III physical regression pass. Controls remain gated by camera or backend advertisement.
- This release still has no signed iOS IPA, and Windows USB control still requires system-provided `gphoto2`/libgphoto2.
