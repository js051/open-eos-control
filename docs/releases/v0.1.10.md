# Open EOS Control v0.1.10 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 第十一個開發預覽版。此版本加入 Canon CCAPI 媒體封存，並提供包含最新跨平台實作的可安裝 Android 與 Desktop Bridge 測試產物。

### 媒體封存

- Android、iOS、PC Desktop Bridge 與 Simulator 現在支援 Canon CCAPI 媒體封存與取消封存。
- 控制只會在相機公告 `PUT /contents` 且媒體資訊回傳可判定的封存狀態時顯示。寫入使用 Canon 定義的 `archive` action 與 `enable`／`disable` value。
- 成功回應後仍會進行最多三次有界 `kind=info` 讀回；只有同一媒體回報預期狀態才算成功並加入 observed evidence。
- Android 與 iOS 的離線預覽只更新本地示範資料，不會假裝已呼叫相機。iOS 中繼資料表單預設使用大尺寸並保留捲動，避免封存與刪除操作落在不可點擊區域。

### 驗證

- PR 與合併後 `main` 都通過 Android API 34／36 Pixel UI、iPhone Simulator app/UI、Swift core、Desktop Bridge、Windows 單檔、Simulator、單元測試與完整歷史敏感資訊掃描。
- 本版的首要真機驗證是使用最新韌體的 EOS R6 Mark III 重新連線，確認 developer API discovery、Still Capture 實拍與新媒體出現，再於 Debug 模式複製已遮蔽序號的診斷與實機確認紀錄。
- HTTP 成功、Simulator 狀態或 supported 清單都不等於真機動作成功；只有成功操作後的 `observedFeatures` 與使用者確認可作為真機證據。

### 下載

- `open-eos-control-android-0.1.10-debug.apk`：使用固定開發簽章的 Android 安裝包，可直接更新 `0.1.5` 以上相同簽章的預覽版。
- `open-eos-control-bridge-windows-x64-0.1.10.exe`：Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.1.10-py3-none-any.whl` 與 `.tar.gz`：Desktop Bridge Python 套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

### 已知限制

- 這是開發預覽版，不建議直接用於正式拍攝流程。媒體封存、快門、事件同步與錄影仍需要 EOS R6 Mark III 最新韌體真機驗證。
- Android USB/PTP 的媒體封存與顯示旋轉，以及 libgphoto2 媒體中繼資料寫入，仍因缺少可靠公開命令與讀回合約而保持不支援。
- iOS USB/PTP 仍屬 Research，Release 不提供可安裝的已簽章 IPA。
- Windows USB 控制仍需要系統可用的 `gphoto2`／libgphoto2；EDSDK 不附 Canon SDK 或可運作 provider。

## English

This is the eleventh Open EOS Control development preview. It adds Canon CCAPI media archive support and packages the latest cross-platform implementation as installable Android and Desktop Bridge test artifacts.

### Media Archive

- Android, iOS, the PC Desktop Bridge, and Simulator can now archive and unarchive Canon CCAPI media.
- Controls appear only when the camera advertises contents `PUT` and media information returns a known archive state. Writes use Canon's `archive` action with the exact `enable` or `disable` value.
- A successful response is followed by up to three bounded `kind=info` reads. Success and observed evidence require the same item to report the requested state.
- Android and iOS offline previews update only local demonstration data. The iOS metadata sheet now opens at a large detent and remains scrollable so archive and delete actions stay reachable.

### Validation

- Both the PR and merged `main` passed Android API 34/36 Pixel UI, iPhone Simulator app/UI, Swift core, Desktop Bridge, standalone Windows, Simulator, unit-test, and full-history secret-scan jobs.
- The priority physical test for this build is reconnecting an EOS R6 Mark III on current firmware, confirming developer API discovery, performing a Still Capture, and verifying that the new media appears before copying the serial-redacted diagnostic and physical-validation record from Debug mode.
- HTTP success, Simulator state, and the supported list do not prove a physical camera action. Physical evidence requires a successful operation in `observedFeatures` plus operator confirmation where the camera-side effect matters.

### Downloads

- `open-eos-control-android-0.1.10-debug.apk`: Android package using the stable development signer; matching previews from `0.1.5` onward can update in place.
- `open-eos-control-bridge-windows-x64-0.1.10.exe`: single-file Windows x64 Desktop Bridge.
- `open_eos_control_bridge-0.1.10-py3-none-any.whl` and `.tar.gz`: Desktop Bridge Python packages.
- `SHA256SUMS.txt`: SHA-256 checksums for every attached file.

### Known Limitations

- This is a Development Preview and is not recommended for production capture workflows. Media archive, capture, event synchronization, and recording still require physical validation on current EOS R6 Mark III firmware.
- Android USB/PTP archive and display rotation, plus libgphoto2 media metadata writes, remain unsupported because no reliable public command and readback contract has been established.
- iOS USB/PTP remains Research, and no installable signed iOS IPA is included.
- Windows USB control still requires a working system `gphoto2`/libgphoto2 installation. No Canon SDK or working EDSDK provider is bundled.
