# Open EOS Control v0.1.3 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 的第四個開發預覽版。本版把既有 Desktop Bridge 製作成可直接執行的 Windows x64 成品，並完成 PC 本機 UVC／HDMI 監看來源。真機驗證仍以 Canon EOS R6 Mark III 為優先；此版本仍是測試用途，不應視為正式拍攝工具。

### 下載

- `open-eos-control-android-0.1.3-debug.apk`：可側載的 Android debug 版本，以 Android SDK debug 憑證簽署。
- `open-eos-control-bridge-windows-x64-0.1.3.exe`：包含 Python runtime、PyAV／FFmpeg 與控制介面的 Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.1.3-py3-none-any.whl`：跨平台 Desktop Bridge Python wheel。
- `open_eos_control_bridge-0.1.3.tar.gz`：Desktop Bridge 原始碼套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

Android APK 與 Windows exe 都不是正式簽章版本；Windows 可能顯示 SmartScreen 警告。Desktop Bridge 的 USB 控制仍需系統提供 `gphoto2`／libgphoto2；無線 CCAPI 與本機 UVC／HDMI 監看不需另外安裝 Python。iOS 目前只提供原始碼，實體裝置版本需使用 Xcode 自行建置與簽署。

### 重點更新

- 新增 Windows x64 standalone Desktop Bridge；雙擊後等待內嵌服務就緒再開啟 loopback 控制頁。
- standalone 內含 Python runtime、PyAV／FFmpeg、FastAPI 服務與完整靜態 UI，Windows CI 會實際啟動 exe 並驗證 UI、CSP、JavaScript、版本與兩個 camera engine。
- LAN 綁定仍強制要求 Bearer token；standalone 不接受 token 命令列參數，避免憑證出現在程序清單。
- PC 取景畫面可切換到瀏覽器管理的本機 UVC 相機或 HDMI 擷取卡，同時保留 Bridge 相機控制 session。
- 本機視訊具明確裝置選擇、真實解碼 FPS、監看輔助、敏感資訊遮蔽，以及來源切換／中斷／頁面關閉時的完整 MediaStream track 清理。
- Playwright 會驗證桌面與窄版配置、相機控制與本機視訊共存、裝置切換、播放失敗、延遲權限競態與 track teardown；release workflow 也會重跑這些瀏覽器測試。

### 已知限制

- 並非所有功能都已在 EOS R6 Mark III 完成完整真機回歸；未由相機公告的能力不會顯示或送出命令。
- Windows standalone 未經程式碼簽章；這是可直接執行的開發成品，不是 MSI／MSIX 安裝程式。
- Windows USB 控制仍需 native gphoto2，或 WSL 2、usbipd-win 與已 attach 的相機；standalone 不會自行安裝或變更這些系統元件。
- UVC 與 HDMI 路徑已有真實瀏覽器 MediaStream 測試，但 R6 Mark III 與實體擷取卡的裝置驗證仍待完成。
- iOS release 不包含已簽署 IPA；Canon CCAPI RTP 目前只處理 H.264 視訊，不含 AAC LATM 音訊。

## English

This is the fourth Open EOS Control development preview. It turns the existing Desktop Bridge into a directly executable Windows x64 artifact and completes local UVC/HDMI preview input for the PC UI. Physical validation still prioritizes the Canon EOS R6 Mark III; this remains a test build and should not be treated as a production capture tool.

### Downloads

- `open-eos-control-android-0.1.3-debug.apk`: sideloadable Android debug build signed with the Android SDK debug certificate.
- `open-eos-control-bridge-windows-x64-0.1.3.exe`: single-file Windows x64 Desktop Bridge containing the Python runtime, PyAV/FFmpeg, and control UI.
- `open_eos_control_bridge-0.1.3-py3-none-any.whl`: cross-platform Desktop Bridge Python wheel.
- `open_eos_control_bridge-0.1.3.tar.gz`: Desktop Bridge source distribution.
- `SHA256SUMS.txt`: SHA-256 checksums for all attached files.

The Android APK and Windows executable are not production-signed; Windows may display a SmartScreen warning. Desktop Bridge USB control still requires system-provided `gphoto2`/libgphoto2. Wireless CCAPI and local UVC/HDMI preview need no separate Python installation. iOS remains source-only; physical-device builds must be built and signed with Xcode.

### Highlights

- Adds a Windows x64 standalone Desktop Bridge that waits for its embedded service before opening the loopback control page.
- Bundles the Python runtime, PyAV/FFmpeg, FastAPI service, and complete static UI; Windows CI launches the executable and verifies the UI, CSP, JavaScript, version, and both camera engines.
- LAN binding still requires a Bearer token. The standalone entry point deliberately has no token command-line argument, preventing credentials from appearing in the process list.
- The PC viewfinder can use a browser-owned local UVC camera or HDMI capture card while retaining the active Bridge camera-control session.
- Local video has explicit device selection, decoded-frame FPS, monitoring assists, redacted diagnostics, and complete MediaStream track cleanup on source switch, disconnect, and page teardown.
- Playwright covers desktop and narrow layouts, camera-control coexistence, device switching, playback failure, delayed-permission races, and track teardown. The release workflow now reruns these browser tests.

### Known Limitations

- Not every feature has completed a full physical regression pass on the EOS R6 Mark III. Commands are exposed only when the camera or backend advertises the required capability.
- The Windows standalone executable is not code-signed. It is a directly executable development artifact, not an MSI/MSIX installer.
- Windows USB control still needs native gphoto2 or WSL 2, usbipd-win, and an attached camera. The standalone executable does not install or modify those system components.
- UVC and HDMI paths have real browser MediaStream coverage, but physical R6 Mark III and capture-card validation remains pending.
- The iOS release does not include a signed IPA. Canon CCAPI RTP currently handles H.264 video only, without AAC LATM audio.
