# Open EOS Control v0.2.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 第十二個開發預覽版，也是第一個 `0.2.x` 版本。此版本集中處理 EOS R6 Mark III 韌體 1.1.0 的協定相容性、Live View 復原、跨平台影片與音訊設定，以及 PC USB 媒體資訊，並以線上 CI 產生 Android 與 Desktop Bridge 測試產物。

### R6 Mark III 與 Live View

- Android、iOS 與 PC 在 `/ccapi` 只回傳版本但沒有有效命令時，會查詢 Canon developer API list；空白、格式錯誤或跨來源資料仍不會產生能力。
- Live View 支援相機只公告 POST 的啟停生命週期、HTTP 400 無尺寸重試、失效公告尺寸降級、multipart 暫時未就緒重試，以及 JPEG polling 的限定 `Device busy` 重試。
- Android RTP 會在五秒內要求收到可解碼、具 SPS/PPS 的關鍵幀；AUTO 失敗時會完整清理，再依序改用 multipart 與 JPEG，不再停在零畫面且沒有錯誤的狀態。
- 要求 FPS 與實測 FPS 分開顯示。真機路徑可設定 6、15、30 FPS，但 30 FPS 是上限要求，不保證相機與網路能持續送滿。

### 相機控制與媒體

- R6 Mark III 公告的影片品質、裁切、錄影格式、整體收音、內建麥克風模式、風切濾波、衰減器與手動收音音量，現在可依相機實際能力呈現在 Android、iOS 與 PC。
- 能力發現、媒體分頁與降級順序、事件停止、iOS 操作面板與 Desktop Bridge FPS 控制已加強，失敗不會留下樂觀的假狀態。
- gPhoto2 USB session 現在可透過既有 media-info API 對指定檔案執行一次唯讀 `--show-info`，並拒絕錯誤區段、畸形輸出與舊快取欄位；暫停的 Live View 會在查詢後恢復。

### 真機與自動驗證

- 生產用 PC CCAPI engine 已對韌體 1.1.0 的實體 EOS R6 Mark III 完成非破壞性測試：118 個公告 GET、28 個可逆設定寫入與精確還原、JPEG／multipart、多次啟停、對焦、事件、媒體資訊、縮圖、顯示預覽與有界記憶體下載。
- 生產路徑 Android debug APK 已透過 Pixel 6 Pro API 34 AVD 連到同一台相機，驗證 246 個公告操作、multipart 畫面、尺寸降級、6／15／30 FPS、500 項媒體清單、縮圖與預覽。這不等同實體手機的 Wi-Fi／行動網路或 USB host 驗證。
- PR 與 `main` 以 Android API 34／36 Pixel UI、iPhone Simulator app/UI、Swift core、Desktop Bridge、Windows 單檔、Simulator、單元測試與完整歷史敏感資訊掃描作為合併閘門。

### 下載

- `open-eos-control-android-0.2.0-debug.apk`：使用固定開發簽章的 Android 安裝包，可直接更新 `0.1.5` 以上相同簽章的預覽版。
- `open-eos-control-bridge-windows-x64-0.2.0.exe`：Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.2.0-py3-none-any.whl` 與 `.tar.gz`：Desktop Bridge Python 套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

### 已知限制

- 這是開發預覽版，不建議直接用於正式拍攝流程。本輪真機測試刻意沒有執行拍照、錄影、Bulb、Click White Balance、媒體修改／刪除、時鐘同步、感光元件清潔、睡眠或關機。
- 相機有公告 RTP，但在目前機身／韌體狀態下啟動回傳 HTTP 503 `Mode not supported`；AUTO 可改用 multipart 或 JPEG，仍不能據此判定所有 R6 Mark III 都無法使用 RTP。
- Android 實體手機、Android USB/PTP、iPhone/iPad 與實體 USB gPhoto2 路徑仍需驗證。Windows USB 控制需要系統可用的 `gphoto2`／libgphoto2。
- Release 不包含已簽章 iOS IPA，也不附 Canon SDK 或可運作的 EDSDK provider。

## English

This is the twelfth Open EOS Control development preview and the first `0.2.x` release. It focuses on EOS R6 Mark III firmware 1.1.0 protocol compatibility, recoverable Live View, cross-platform movie and audio settings, and PC USB media information. Online CI produces the Android and Desktop Bridge test packages.

### R6 Mark III And Live View

- Android, iOS, and PC query Canon's developer API list when `/ccapi` identifies protocol versions but yields no valid commands. Empty, malformed, or cross-origin data still creates no capability.
- Live View now handles cameras that advertise a POST-only lifecycle, HTTP 400 retry without a size, invalid advertised-size downgrade, transient multipart readiness, and narrowly scoped JPEG-polling `Device busy` retries.
- Android RTP requires a decodable SPS/PPS-backed key frame within five seconds. AUTO fully cleans a failed source before falling through to multipart and JPEG instead of remaining at a silent zero-frame state.
- Requested and observed FPS remain separate. The physical path accepts 6, 15, and 30 FPS requests, but 30 FPS is a cap rather than a throughput guarantee.

### Camera Controls And Media

- Camera-advertised R6 Mark III movie quality, cropping, recording format, overall sound recording, internal microphone mode, wind filter, attenuator, and manual recording level are now capability-gated across Android, iOS, and PC.
- Discovery, media pagination and fallback ordering, event cleanup, the iOS control panel, and Desktop Bridge FPS handling are more resilient and do not retain optimistic state after failures.
- gPhoto2 USB sessions now serve one fresh, read-only `--show-info` query for a selected file through the existing media-info API. Wrong sections, malformed output, and stale cached fields are rejected, and a paused Live View stream is restored afterwards.

### Physical And Automated Validation

- The production PC CCAPI engine completed a non-destructive pass against a physical EOS R6 Mark III on firmware 1.1.0: 118 advertised GET resources, 28 reversible setting writes with exact restoration, JPEG and multipart Live View, repeated restarts, focus, events, media information, thumbnail/display preview, and a bounded in-memory download.
- A production-path Android debug APK reached the same camera through a Pixel 6 Pro API 34 AVD and validated 246 advertised operations, multipart frames, size downgrade, 6/15/30 FPS control, a bounded 500-item media list, thumbnails, and display preview. This is not physical-phone Wi-Fi/cellular or USB-host evidence.
- Pull requests and `main` are gated by Android API 34/36 Pixel UI, iPhone Simulator app/UI, Swift core, Desktop Bridge, standalone Windows, Simulator, unit-test, and full-history secret-scan jobs.

### Downloads

- `open-eos-control-android-0.2.0-debug.apk`: Android package using the stable development signer; matching previews from `0.1.5` onward can update in place.
- `open-eos-control-bridge-windows-x64-0.2.0.exe`: single-file Windows x64 Desktop Bridge.
- `open_eos_control_bridge-0.2.0-py3-none-any.whl` and `.tar.gz`: Desktop Bridge Python packages.
- `SHA256SUMS.txt`: SHA-256 checksums for every attached file.

### Known Limitations

- This is a Development Preview and is not recommended for production capture workflows. This physical pass intentionally did not invoke capture, recording, Bulb, Click White Balance, media mutation/deletion, clock sync, sensor cleaning, sleep, or power commands.
- The camera advertised RTP but returned HTTP 503 `Mode not supported` in its current body/firmware state. AUTO can fall back to multipart or JPEG; this does not prove that RTP is unavailable on every R6 Mark III.
- Physical Android phones, Android USB/PTP, iPhone/iPad, and physical USB gPhoto2 paths still require validation. Windows USB control requires a working system `gphoto2`/libgphoto2 installation.
- The release contains no signed iOS IPA, Canon SDK material, or working EDSDK provider.
