# Open EOS Control v0.7.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

`0.7.0` 新增 Android 相機回報的對焦框與狀態，並修正遠端即時取景的停止／恢復。本版是 Development Preview，不是穩定版；minor 版號代表新增可操作能力，不代表機身失焦問題已解決。

### Android 變更

- 相機公告 Canon `flipdetail?kind=info` 時，讀取所選 AF 框的實際座標及合焦、未合焦、Servo 進行中等狀態。框線改為四角細線，中央不遮擋。
- 綠色只代表相機回報合焦；App 的 AF、半按、焦點移動及 AF 點命令成功仍是中性的「已接受」，不能代替相機合焦結果或成片銳利度驗證。
- AF 資料讀取有大小、數量與時間上限。過期超過一秒即隱藏；錯誤清除框線並保留 Debug 摘要，不中斷影像串流。離線、取景暫停或尚未取得影像時不疊框。
- 關閉「遠端即時取景」或 App 進入背景，會真正停止相機端 Live View。回到前景只在使用者仍開啟取景時恢復，Refresh、尺寸調整不會偷偷打開已關閉的取景。
- 取景切換保留拍攝、對焦、Bulb 的清理次序。停止失敗會顯示錯誤並可重試，不把失敗假裝成成功。

### 驗證與限制

- 功能 PR #181、#182 的 exact-head CI 與 main acceptance 通過；Android unit、APK、API 34／36 UI 測試有對應證據。最新功能本地 487 項 unit tests、lint/build 與 HTC U24 Pro 的 15 項 instrumentation 通過。
- HTC instrumentation 使用本機 MockWebServer；這不等於實體 R6 Mark III AF 驗收。AF 資料座標、各 AF 模式與持續讀取負載仍待實機確認。
- 先前 HTC／R6 Mark III Wi-Fi 調查已觀察到新版本關閉取景後相機回覆 `Live view not started`，但操作者暫時無法比較機身半按與成片，因此「連 App 後容易失焦」的因果關係仍未確認。沒有寫入 AF operation、AF method 或 tracking 設定。
- 本輪 AF 疊框只支援 1x 且 metadata／顯示影像比例相符；放大、anamorphic desqueeze、無效或未知幾何時不猜測框位置。按住 AF-ON／持續 Servo 操作仍未完成，不宣稱與 Camera Connect 功能等價。
- 新行為只在 Android。PC／iOS 僅對齊產品版本並沿用現有功能與測試，不宣稱同步了 AF metadata 或這次取景生命週期變更。
- Camera Import contract 維持 artifact `1.1.0`／wire `1.0`；Serein 整合契約未改。

協定與測試細節：[取景停止調查](../validation/android-focus-session-2026-09-06.zh-TW.md)、[AF 框與狀態](../validation/android-af-frame-feedback-2026-09-06.zh-TW.md)。

### 安裝與發行檔

- Android：`open-eos-control-android-0.7.0-debug.apk` 沿用固定開發簽章與正式 Preview package，可覆蓋安裝同簽章的舊 Preview；不會覆蓋獨立的 `.debug` 測試 App。
- PC：提供版本對齊的 Windows x64 Bridge executable、Python wheel 與 source distribution。
- iOS：保留原始碼與 iPhone Simulator CI，本版不提供可直接安裝的已簽署 IPA。
- 另附 Camera Import schema ZIP、Kotlin JAR、`BUILD-PROVENANCE.json` 與 `SHA256SUMS.txt`。發行檔由專用 Actions workflow 提升 exact-main immutable candidate，不手動重建替換 APK。

## English

`0.7.0` adds Android camera-reported AF frames and status, alongside corrected remote Live View stop/resume behavior. This is a Development Preview, not a stable release. The minor version denotes a new usable capability, not resolution of the reported camera-body defocus problem.

### Android Changes

- An advertised Canon `flipdetail?kind=info` endpoint supplies selected AF coordinates and focus-acquired, unsuccessful, Servo-in-progress, standby, or unknown state. Sparse corner strokes leave the subject center unobstructed.
- Green means the camera reported focus acquired. AF, half-press, focus-drive, and AF-point command success remains neutral acknowledgement, distinct from camera focus state and verified photograph sharpness.
- Metadata reads have bounded size, count, and duration. Frames expire after one second without fresh data; read failures clear them without stopping the image stream. Offline, paused, or image-unavailable views do not display camera AF overlays.
- Turning remote Live View off or backgrounding Android now stops the camera-side stream. Foregrounding resumes only when the user still requests Live View; refresh and size changes cannot silently re-enable it.
- Transitions preserve capture, focus, and Bulb cleanup ordering. Stop failures remain visible and retryable rather than being reported as success.

### Evidence And Limitations

- Feature PRs #181 and #182 passed exact-head CI and main acceptance, including Android unit/APK and API 34/36 UI evidence. The latest feature passed 487 local unit tests, lint/build, and 15 HTC U24 Pro instrumentation tests.
- HTC instrumentation uses a local MockWebServer, not physical R6 Mark III AF validation. Actual AF geometry/modes and sustained metadata-read load remain pending.
- Earlier HTC/R6 Mark III Wi-Fi observation confirmed that the corrected remote-off behavior produced `Live view not started`. The operator could not compare body half-press and resulting photographs, so the cause of reported body-side defocus remains unconfirmed. AF operation, method, and tracking settings were not changed.
- Overlays require 1x magnification and matching metadata/image aspect ratio. Magnified, desqueezed, invalid, or unknown geometry is not guessed. Press-and-hold AF-ON/continuous Servo remains pending; Camera Connect feature equivalence is not claimed.
- New behavior is Android-only. PC/iOS have aligned product versions and existing functionality/tests, without parity for this AF metadata or Live View lifecycle work.
- Camera Import stays at artifact `1.1.0` / wire `1.0`; the Serein integration contract is unchanged.

See the [Live View investigation](../validation/android-focus-session-2026-09-06.zh-TW.md) and [AF metadata evidence](../validation/android-af-frame-feedback-2026-09-06.zh-TW.md).

### Distribution

- `open-eos-control-android-0.7.0-debug.apk` retains the persistent development signer and Preview package, updating matching older previews without replacing the separate `.debug` acceptance app.
- Version-aligned PC assets include the Windows x64 Bridge executable, Python wheel, and source distribution. iOS remains source plus iPhone Simulator CI; no installable signed IPA is provided.
- Camera Import schema ZIP, Kotlin JAR, `BUILD-PROVENANCE.json`, and `SHA256SUMS.txt` accompany the release. The dedicated Actions workflow promotes the exact-main immutable candidate without manually rebuilding or substituting release files.
