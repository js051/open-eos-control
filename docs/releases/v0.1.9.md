# Open EOS Control v0.1.9 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 第十個開發預覽版。此版本把 `v0.1.8` 後完成的 CCAPI 韌體探索修正、跨平台控制與媒體流程，以及 Android 直接 USB/PTP 擴充打包成可安裝、可驗證的版本。

### 韌體相容性與控制

- Canon 回報協定版本但 root operation list 沒有有效命令時，Android、iOS 與 PC 會改查 `/ccapi/ver100/topurlfordev`。只有通過同源與方法／路徑驗證的命令才會形成能力；空白、格式錯誤或失敗的 developer list 仍保持 fail-closed。
- 三個平台補強相機模式、事件同步、鏡頭與溫度狀態、錄影品質與聲音設定、Focus Bracketing、Auto Power Off、感光元件清潔、Live View 動態放大與持續 multipart JPEG fallback。
- 能力探索比舊版嚴格。相機未公告、回應格式不完整或無法可靠讀回的控制會保持隱藏，而不會依機型或韌體名稱猜測支援。

### 媒體與 Android USB

- Android 直接 USB 與 Android／iOS Bridge client、PC Desktop Bridge 新增具能力檢查、取消與完整性驗證的媒體上傳。Canon CCAPI 直接上傳仍明確不支援。
- CCAPI 媒體可依公告能力變更保護、0-5 評分與顯示旋轉；Android 直接 USB 另支援標準 PTP 保護，以及只有在完整 MTP Rating descriptor 與六個可寫值都成立時才開放的評分。
- Android 直接 USB/PTP 增加 Photo／Video 模式切換、鏡頭狀態、文字中繼資料、錄影狀態與未知 Canon property 結構診斷。未知值、raw bytes、字串與 custom-function 內容不會寫入診斷報告。

### 驗證與隱私

- CI 涵蓋 Android API 34／36 Pixel 工作流、iPhone Simulator、PC browser、真實 HTTP preset 路徑、Windows 單檔 Desktop Bridge、跨平台事件競態與媒體操作。
- 診斷與真機驗證報告遮蔽認證資料、相機序號、URL 與本機資訊。未知 Canon property 只留下有界的代碼、事件類型、封包長度與列舉結構。
- 無已知 breaking changes，也不需要資料庫或使用者設定遷移。更新後建議重新連線並重新整理相機能力。

### 下載

- `open-eos-control-android-0.1.9-debug.apk`：使用固定開發簽章的 Android 安裝包，可直接更新 `0.1.5` 以上相同簽章的預覽版。
- `open-eos-control-bridge-windows-x64-0.1.9.exe`：Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.1.9-py3-none-any.whl` 與 `.tar.gz`：Desktop Bridge Python 套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

### 已知限制

- 這是開發預覽版，不建議直接用於正式拍攝流程。自動化測試與 Simulator 不等於 EOS R6 Mark III 真機驗證。
- iOS USB/PTP 仍屬 Research，Release 不提供可安裝的已簽章 IPA。
- Windows USB 控制仍需要系統可用的 `gphoto2`／libgphoto2；EDSDK 目前只有 SDK-neutral provider 邊界，不附 Canon SDK 或可運作 provider。
- Android MTP 評分需要相機公告完整可寫 descriptor；USB 媒體旋轉仍不可用。
- RTP、multipart、媒體上傳與 USB throughput 仍依相機公告及本機能力而定，需要進一步 R6 Mark III 真機回歸。

## English

This is the tenth Open EOS Control development preview. It packages the CCAPI firmware-discovery fix, broader cross-platform controls and media workflows, and direct Android USB/PTP additions completed after `v0.1.8`.

### Firmware Compatibility And Controls

- When Canon reports a protocol version but no valid root operations, Android, iOS, and PC now query `/ccapi/ver100/topurlfordev`. Only validated same-origin methods and paths become capabilities; empty, malformed, or failed developer lists remain fail-closed.
- All three platforms add broader camera-mode and event synchronization, lens and temperature status, movie quality and sound settings, Focus Bracketing, Auto Power Off, sensor cleaning, Live View magnification, and persistent multipart JPEG fallback.
- Discovery is intentionally stricter. Controls remain hidden when the camera does not advertise a complete contract or the state cannot be read back reliably; support is never inferred from only a model or firmware name.

### Media And Android USB

- Direct Android USB, Android/iOS Bridge clients, and the PC Desktop Bridge add capability-gated media upload with cancellation and integrity verification. Direct Canon CCAPI upload remains explicitly unsupported.
- Advertised CCAPI media can change protection, 0-5 rating, and display rotation. Direct Android USB separately supports standard PTP protection and exposes rating only after proving a complete MTP Rating descriptor with all six writable values.
- Direct Android USB/PTP adds Photo/Video switching, lens status, wired text metadata, recording-state readback, and structural diagnostics for unknown Canon properties. Unknown values, raw bytes, strings, and custom-function contents are excluded.

### Validation And Privacy

- CI covers Android API 34/36 Pixel workflows, iPhone Simulator, PC browser, production HTTP-preset paths, the standalone Windows Desktop Bridge, cross-platform event races, and media operations.
- Diagnostics and physical-validation reports redact credentials, camera serials, URLs, and local information. Unknown Canon properties retain only bounded codes, event kinds, packet lengths, and enumeration structure.
- There are no known breaking changes and no database or user-settings migration. Reconnect and refresh camera capabilities after upgrading.

### Downloads

- `open-eos-control-android-0.1.9-debug.apk`: Android package using the stable development signer; matching previews from `0.1.5` onward can update in place.
- `open-eos-control-bridge-windows-x64-0.1.9.exe`: single-file Windows x64 Desktop Bridge.
- `open_eos_control_bridge-0.1.9-py3-none-any.whl` and `.tar.gz`: Desktop Bridge Python packages.
- `SHA256SUMS.txt`: SHA-256 checksums for every attached file.

### Known Limitations

- This is a Development Preview and is not recommended for production capture workflows. Automated and Simulator coverage does not replace physical EOS R6 Mark III validation.
- iOS USB/PTP remains Research, and no installable signed iOS IPA is included.
- Windows USB control still requires a working system `gphoto2`/libgphoto2 installation. EDSDK is represented only by an SDK-neutral provider boundary; no Canon SDK or working provider is bundled.
- Android MTP rating requires the complete advertised writable descriptor; USB media rotation remains unavailable.
- RTP, multipart, media upload, and USB throughput still depend on camera advertisement and local capability, and require further R6 Mark III physical regression testing.
