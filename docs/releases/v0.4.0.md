# Open EOS Control v0.4.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這個 `0.4.0` 開發預覽版改善 Android、iOS 與 PC 在拍照後立即檢視最近素材的流程。連線及成功拍照後只讀取最多八筆相機排序的素材，讓取景畫面旁的最近媒體入口可以快速出現，不必先列舉數千個檔案。需要整理整張記憶卡時，完整媒體瀏覽仍保留明確入口。

### 拍攝後快速預覽

- Android、iOS 與 PC 在連線及成功拍照後取得最多八筆最近素材，並以有限次重試等待相機發布新檔。
- 偵測到新素材後，取景畫面旁會顯示最近媒體縮圖；點擊後直接開啟既有相片或影片檢視器。
- 新縮圖準備完成前保留上一張有效縮圖，減少相機 Wi-Fi 暫時延遲造成的閃爍與空白。
- 媒體或縮圖補充失敗不會把已成功的快門結果改寫為失敗，也不會偽造拍攝成功。
- Android 縮圖解碼限制在 512 px 內，背景工作具備取消與連線世代保護，診斷只記錄最近素材是否可用，不輸出素材識別碼。

### 大型記憶卡與跨平台一致性

- iOS 與 PC 現在和 Android 一樣提供「最近」及「整張記憶卡」範圍，部分結果不會冒充完整總數。
- Desktop Bridge API 支援 `limit=1..1000`；Direct CCAPI 達到最近素材數量後可提早停止媒體葉節點列舉，同時仍檢查相片與影片容器。
- Simulator 為新拍素材產生拍攝時間，跨平台自動測試可重現驗證最近排序、快捷入口與實際 viewer 導航。

### 可追溯發版流程

- 完整安全、Android、iOS、Bridge、Windows 與 Simulator 矩陣只在版本 PR 的 exact SHA 執行。
- `main` 會驗證 squash merge 的 Git tree 與成功 PR 完全一致，沿用已測 Bridge／Windows candidates，只補建需要 repository secret 的固定簽章 Android APK。
- tag 會發布同一份 provenance-checked candidate，不再重新建置或手動替換 release 檔案。

### 下載與限制

- `open-eos-control-android-0.4.0-debug.apk` 使用既有固定開發簽章，可覆蓋安裝 v0.1.5 之後的同簽章預覽版。
- Release 同時提供 Windows x64 Desktop Bridge、Bridge Python wheel/source archive、`BUILD-PROVENANCE.json` 與 SHA-256 校驗值。
- 本版不提供可安裝的 iOS IPA；iOS App 與 UI 由 macOS CI 編譯及 Simulator 驗證，實體裝置仍需開發者自行簽章。
- 本批沒有連接實體 EOS R6 Mark III。真機 CCAPI 拍攝後的素材發布延遲、相機排序、大型記憶卡耗時、影片 codec 與 USB/PTP 行為仍需持續驗證。

## English

This `0.4.0` development preview improves the workflow for reviewing a just-captured item on Android, iOS, and PC. After connection and a successful still capture, each client requests at most eight camera-ordered items so the recent-media shortcut can appear without first enumerating thousands of files. Explicit full-card browsing remains available for complete card management.

### Post-Capture Quick Review

- Android, iOS, and PC fetch at most eight recent items after connection and successful still capture, with bounded retries while the camera publishes a new file.
- Once a new item is detected, a recent-media thumbnail appears beside the viewfinder and opens the existing photo or video viewer directly.
- The previous valid thumbnail remains visible until its replacement is ready, reducing blank states during temporary camera Wi-Fi delays.
- Supplemental media or thumbnail failures cannot rewrite a successful shutter result, and the clients never fabricate capture success.
- Android thumbnail decoding is bounded to 512 px. Background work has cancellation and connection-generation guards, while diagnostics expose only whether recent media is available and never include the media identifier.

### Large Cards And Cross-Platform Consistency

- iOS and PC now join Android in providing explicit Recent and Full card scopes; partial results are never presented as a complete total.
- The Desktop Bridge API accepts `limit=1..1000`. Direct CCAPI can stop media-leaf enumeration once enough recent items are available while still sampling sibling photo and video containers.
- Simulator captures receive generated capture timestamps so cross-platform automation can reproducibly validate recent ordering, shortcut availability, and real viewer navigation.

### Traceable Delivery

- The complete security, Android, iOS, Bridge, Windows, and Simulator matrix runs once for the exact version-PR SHA.
- `main` verifies that the squash-merged Git tree exactly matches the successful PR, reuses the tested Bridge and Windows candidates, and only adds the stable-signed Android APK that requires repository secrets.
- The version tag publishes that same provenance-checked candidate without rebuilding or manually substituting release files.

### Downloads And Limitations

- `open-eos-control-android-0.4.0-debug.apk` uses the existing stable development signer and can update matching previews from v0.1.5 onward.
- The release also includes the Windows x64 Desktop Bridge, Bridge Python wheel/source archive, `BUILD-PROVENANCE.json`, and SHA-256 checksums.
- No installable iOS IPA is included. The iOS app and UI are built and Simulator-tested by macOS CI; physical-device installation still requires developer signing.
- No physical EOS R6 Mark III was connected for this batch. Camera-side post-capture propagation, ordering, large-card latency, video-codec compatibility, and USB/PTP behavior still require continued device validation.
