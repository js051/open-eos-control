# Open EOS Control v0.3.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 第十三個開發預覽版，也是第一個 `0.3.x` 版本。本版集中改善 Android、iOS 與 PC 的相機媒體工作流程，讓大型記憶卡、照片檢視與相機內影片播放成為可持續測試的完整功能，而不是只顯示有限筆數或無法播放的預覽入口。

### 大型媒體庫

- 移除舊版 500 筆固定上限。Direct CCAPI 會走完相機公告的全部媒體容器與頁面，Android 與 iOS 在過程中逐頁顯示結果，並可取消載入。
- 媒體摘要明確區分 `LOADING`、`COMPLETE`、`CANCELLED` 與 `FAILED`；只有 `COMPLETE` 的數量代表完成遍歷的總數。
- 保留相機傳回順序，同時提供自然檔名、拍攝日期、照片／影片篩選與日期分組。不同容器會公平合併，避免大量照片遮蔽影片。
- 自動化測試覆蓋超過 500 筆的跨頁清單。v0.3.0 仍需使用實體 R6 Mark III 與大型記憶卡重新確認完整清單耗時及長時間穩定性。

### 照片與素材詳情

- Android、iOS 與 PC 提供全畫面照片檢視、受邊界限制的縮放與平移、縮圖及相機 display preview。
- Android USB/PTP 與 Desktop Bridge/libgphoto2 保留可驗證的 MIME、解析度、檔案大小與拍攝時間；缺少可靠協定資料時保持未知，不猜測值。
- 只讀詳情不再依賴保護、評分、旋轉或封存等寫入能力。寫入與刪除仍各自依相機公告能力開放。

### 相機內影片播放

- Android 使用 Media3、iOS 使用 AVFoundation resource loader、PC 使用具 Range 驗證的 Bridge 播放端點，支援相機內影片串流與必要時的完整檔案暫存退路。
- 播放來源會驗證 Range、宣告長度與完整檔案；取消、網路、暫存空間與傳輸錯誤不會留下半成品。
- 播放失敗可在原位置重試。缺少裝置解碼器時會顯示實際容器限制並保留原檔下載，不假裝重試能新增 codec。

### 驗證與下載

- PR 與 `main` 已通過 Android API 34／36 UI、iPhone Simulator App/UI、Swift Core、Desktop Bridge、Windows bundle、Simulator、完整單元測試與歷史敏感資訊掃描。
- `open-eos-control-android-0.3.0-debug.apk`：使用既有固定開發簽章，可覆蓋安裝 v0.1.5 之後相同簽章的預覽版。
- `open-eos-control-bridge-windows-x64-0.3.0.exe`：Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.3.0-py3-none-any.whl` 與 `.tar.gz`：Desktop Bridge Python 套件。
- `SHA256SUMS.txt`：所有發版檔案的 SHA-256 校驗值。

### 已知限制

- 這仍是 Development Preview，不建議用於不可重拍的正式工作。v0.2.0 後的媒體重構尚未在實體 Android 手機上走完超過 500 筆的 R6 Mark III 清單。
- 相機內影片能否直接播放仍取決於相機 HTTP Range 行為、檔案容器、影片 codec 與手機／電腦的解碼器；必要時 App 會嘗試經驗證的完整暫存，但不保證每個 Canon 錄影格式都能解碼。
- Android USB/PTP、實體 iPhone/iPad 與實體 USB gPhoto2 的新版媒體流程仍需擴大真機驗證。Windows USB 控制需要可工作的系統 `gphoto2`／libgphoto2 安裝。
- Release 不包含簽章 iOS IPA、Canon SDK 內容或可用的 EDSDK provider。

## English

This is the thirteenth Open EOS Control development preview and the first `0.3.x` release. It focuses on making large camera-card browsing, photo inspection, and camera-resident video playback complete, testable workflows across Android, iOS, and PC instead of limited lists or non-functional preview entries.

### Large Media Libraries

- Removed the old fixed 500-item limit. Direct CCAPI traverses every camera-advertised media container and page, while Android and iOS publish completed pages progressively and allow cancellation.
- Media summaries distinguish `LOADING`, `COMPLETE`, `CANCELLED`, and `FAILED`. Only a `COMPLETE` count represents a finished traversal.
- Camera order is preserved alongside natural-name and capture-date sorting, photo/video filtering, and date grouping. Fair container merging prevents a large photo container from hiding videos.
- Automated tests cover pagination beyond 500 items. v0.3.0 still needs a fresh physical R6 Mark III large-card pass to measure full-list latency and long-running stability.

### Photos And Media Details

- Android, iOS, and PC provide full-screen photo viewing, bounded zoom and pan, thumbnails, and camera display previews.
- Android USB/PTP and Desktop Bridge/libgphoto2 retain verifiable MIME type, dimensions, file size, and capture time. Unknown fields remain unknown when a transport has no reliable protocol evidence.
- Read-only details no longer depend on protection, rating, rotation, or archive write support. Every mutation and deletion remains independently capability-gated.

### Camera-Resident Video Playback

- Android uses Media3, iOS uses an AVFoundation resource loader, and PC uses range-validated Bridge playback endpoints, with exact full-file staging when direct camera streaming cannot seek reliably.
- Playback validates byte ranges, declared lengths, and completed staged files. Cancellation, network, storage, and transport failures do not retain partial files.
- In-place retry rebuilds failed playback sources. Codec failures identify the actual container and retain original download without claiming that retry can install a missing decoder.

### Validation And Downloads

- Pull requests and `main` passed Android API 34/36 UI, iPhone Simulator app/UI, Swift Core, Desktop Bridge, Windows bundle, Simulator, full unit tests, and full-history secret scanning.
- `open-eos-control-android-0.3.0-debug.apk`: Android package using the existing stable development signer; matching previews from v0.1.5 onward can update in place.
- `open-eos-control-bridge-windows-x64-0.3.0.exe`: single-file Windows x64 Desktop Bridge.
- `open_eos_control_bridge-0.3.0-py3-none-any.whl` and `.tar.gz`: Desktop Bridge Python packages.
- `SHA256SUMS.txt`: SHA-256 checksums for every release file.

### Known Limitations

- This remains a Development Preview and is not recommended for irreplaceable production work. The post-v0.2.0 media rewrite has not yet completed a greater-than-500-item R6 Mark III traversal on a physical Android phone.
- Direct camera-video playback still depends on camera HTTP Range behavior, file container, video codec, and device decoders. The app can stage a verified complete file when appropriate, but cannot guarantee decoding for every Canon recording format.
- The revised Android USB/PTP, physical iPhone/iPad, and physical USB gPhoto2 media paths still need broader device validation. Windows USB control requires a working system `gphoto2`/libgphoto2 installation.
- The release contains no signed iOS IPA, Canon SDK material, or working EDSDK provider.
