# Open EOS Control v0.8.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

`0.8.0` 新增 Android 直連 CCAPI 的按住 AF-ON。這是可下載測試的新操作能力，因此採 minor 版號；仍是 Development Preview，不是穩定版，也不代表先前回報的機身失焦問題已解決。

### Android 變更

- 相機明確公告原生 `POST /shooting/control/af` 時才顯示 AF-ON。手指按下送 start，放開或取消送 stop，使用相機公告的 API 版本；不以半按快門能力推定支援。
- AF-ON 使用固定 56 dp 觸控區，與放大控制分開，只有內容隨方向旋轉。提供英文／繁中說明與狀態；無障礙與鍵盤的一般啟用仍使用既有有界短按操作。
- 視窗失焦、隱藏 HUD、開設定、離開控制頁、關閉遠端取景、切到背景或斷線皆要求停止 AF。開始回應尚未返回時放開，也保留停止責任；回到前景不會自行重新開始。
- 停止失敗顯示可重試警告，只重送 stop，不重送 start；未確認停止前阻擋新的對焦、拍攝、錄影切換與曝光設定等衝突命令。
- 保留 v0.7.0 的相機回報 AF 框與遠端取景停止／恢復。命令被接受、相機回報合焦、成片真正銳利是不同證據，不以成功 HTTP 回應偽造綠色合焦。

### 驗證與限制

- 功能 [PR #184](https://github.com/js051/open-eos-control/pull/184) 的 exact-head [CI](https://github.com/js051/open-eos-control/actions/runs/34026506498) 與 [main acceptance](https://github.com/js051/open-eos-control/actions/runs/34027163480) 通過。包含 Android unit/build、API 34／36 UI；本地 494 項 unit tests、lint/build 通過。
- HTC U24 Pro 使用本機 MockWebServer 完成 26 項對焦／生命週期／排版回歸；後續新增／修訂的失焦與手勢兩項測試連續五輪通過。排版涵蓋三種尺寸、四方向、繁中 1.5 倍字體及明確的安全區域，這不等於所有小視窗與長文字已全面驗收。
- 本輪沒有向實體 R6 Mark III 發送 AF 或拍攝命令。操作者暫時無法比較機身半按與照片，原失焦原因、各 AF 模式效果、實際釋放與持續使用負載仍待確認。
- 不自動更改 One-Shot／Servo、AF method 或 tracking。按住 start 不保證機身目前模式會持續追蹤，也不宣稱與 Camera Connect 功能等價。
- **先放開 AF-ON，再按 App 快門。** 本輪不支援按住 AF 同時按 App 快門。開始確認後最多持有 30 秒便要求停止；這是 App 內保護，不是相機端租約。程序強殺或網路中斷後，不能保證 stop 已送達，需要確認機身狀態。
- 新功能僅在 **Android 直連 CCAPI**。PC／iOS 僅對齊產品版本；Android USB／Bridge、簡化 Simulator preset 與離線預覽不提供未實作的按住 AF。
- Camera Import contract 維持 artifact `1.1.0`／wire `1.0`，Serein 契約與責任邊界未變。

詳細協定、失敗清理與測試記錄：[Android 按住 AF-ON](../validation/android-held-autofocus-2026-09-06.zh-TW.md)。

### 安裝與發行檔

- Android：`open-eos-control-android-0.8.0-debug.apk`，`versionCode=22`，沿用固定開發簽章與 Preview package，可更新同簽章的舊 Preview；不覆蓋獨立 `.debug` 測試 App。
- PC：提供版本對齊的 Windows x64 Bridge executable、Python wheel 與 source distribution，未加入本輪按住 AF 功能。

- 另附 Camera Import schema ZIP、Kotlin JAR、`BUILD-PROVENANCE.json` 與 `SHA256SUMS.txt`。專用 Actions workflow 發布 exact-main immutable candidate，不手動重建替換發行檔。

## English

`0.8.0` adds press-and-hold AF-ON for Android direct CCAPI. This new testable interaction warrants a minor version, but remains a Development Preview, not a stable release or a claim that the reported camera-body defocus is resolved.

### Android Changes

- AF-ON appears only for an advertised native `POST /shooting/control/af` operation. Press sends start; release/cancellation sends stop using the advertised API version. Half-press capability alone does not imply held AF support.
- A fixed 56 dp target stays separate from magnification, rotating only its content. English/Traditional Chinese descriptions and states are included. Accessibility and keyboard activation retain the existing bounded AF operation.
- Window focus loss, hidden HUD, settings/navigation changes, remote Live View off, backgrounding, and disconnect request stop. Release during an outstanding start response still retains cleanup responsibility; returning to the foreground never restarts AF automatically.
- An unconfirmed stop retains a visible stop-only retry, without restarting AF, and blocks conflicting focus, capture, recording transitions, and exposure writes.
- Camera-reported AF frames and Live View lifecycle behavior from v0.7.0 remain. HTTP acknowledgement, camera-reported focus, and verified image sharpness are separate; acknowledgement alone never produces a green focus confirmation.

### Evidence And Limitations

- Feature [PR #184](https://github.com/js051/open-eos-control/pull/184) passed exact-head [CI](https://github.com/js051/open-eos-control/actions/runs/34026506498) and [main acceptance](https://github.com/js051/open-eos-control/actions/runs/34027163480), including Android unit/build and API 34/36 UI. Local validation passed 494 unit tests and lint/build.
- HTC U24 Pro ran 26 focus/lifecycle/layout regressions against a local MockWebServer. Two subsequently added/revised window-focus and gesture tests passed five consecutive runs. Three viewport sizes, four angles, Traditional Chinese at 1.5 font scale, and explicit safe areas were checked, not every compact window or long label in the entire app.
- No physical R6 Mark III AF/capture commands were sent during this feature's validation. The operator could not compare body half-press and photographs; the original defocus cause, AF-mode behavior, actual release, and sustained load remain pending.
- Camera One-Shot/Servo, AF method, and tracking settings are unchanged. Holding start does not guarantee continuous tracking in the current camera mode or Camera Connect feature equivalence.
- **Release AF-ON before pressing the App shutter.** Simultaneous held AF and App capture is not implemented. After start acknowledgement, the App requests stop after at most 30 seconds. This is not a camera-side lease: process death or network loss can prevent stop delivery and requires checking the camera.
- New behavior is **Android direct CCAPI only**. PC/iOS versions are aligned without held-AF parity; Android USB/Bridge, the simplified Simulator preset, and offline preview do not offer an unimplemented held-AF control.
- Camera Import stays at artifact `1.1.0` / wire `1.0`; the Serein contract is unchanged.

See [held-AF protocol and validation details](../validation/android-held-autofocus-2026-09-06.zh-TW.md).

### Distribution

- `open-eos-control-android-0.8.0-debug.apk`, `versionCode=22`, retains the persistent development signer and Preview package. It updates matching older previews without replacing the separate `.debug` test app.
- Version-aligned PC assets include a Windows x64 Bridge executable, wheel, and source distribution, without this held-AF feature. iOS remains source plus Simulator CI; no installable signed IPA is provided.
- Camera Import schema ZIP, Kotlin JAR, provenance, and checksums accompany the release. The dedicated Actions workflow promotes the exact-main immutable candidate, without manually rebuilding or substituting release files.
