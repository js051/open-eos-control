# Open EOS Control v0.13.0 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

`0.13.0` 新增 Android 本次直接 CCAPI 連線的前景 JPEG 自動交付。使用者可先明確啟用，再在 App 保持前景時把新觀察到的 JPEG 原檔保存至手機 Gallery。這是一組新使用者功能，因此採 minor 版號；仍是供測試與回饋的 **Development Preview**，不建議用於正式拍攝流程。

### 使用方式與範圍

1. 使用 Android 10+ 直接連線 CCAPI，從相簿開啟前景自動儲存，閱讀新 JPEG 範圍、儲存位置、前景限制及清理提醒後啟用。
2. 等待兩次完整、有界且相符的起始清單完成。原本已存在的檔案不會補匯入；起始最多 2000 項，清單不完整或超限時顯示原因並停止。
3. 保持 App 在前景。只有新觀察到、符合 JPEG 條件且兩次新鮮正數大小在至少一秒間隔後一致的候選，才以單次原檔 GET 寫入 MediaStore pending row；完整寫入、關閉及長度確認後才公開至 Gallery。新 ID 只代表新觀察，不保證是本次連線或本次快門拍攝。
4. 查看排隊與完成結果，或按 Stop。記憶項上限 4096，排隊含保存中的上限 20；超限或部分 listing 不會被當成成功掃描。Stop、背景與連線替換會取消並等待本次工作清理；回前景或重新連線都要再次明確啟用。

清理未確認會留下可見警告；確認警告不等於檔案已清除。已公開的完整原檔不因稍後取消或紀錄失敗而刪除。自動下載失敗不重試原檔或重播快門、錄影、對焦等相機命令。控制畫面沒有匯入狀態列時維持原完整 viewport，有狀態列時只消耗一次系統 insets；held-AF、縮放及安全區域斷言均保留。

### 升級與限制

- Android **0.13.0 / versionCode 29**，沿用 Preview package 與固定開發簽章；更新需相同 package／簽章，隔離 `.debug` 測試 App 仍為另一安裝。
- iOS **0.13.0 / build 27**、Bridge／Simulator 同步產品版本；新增前景匯入限 Android 直接 CCAPI，版號同步不代表 iOS、PC、USB 或 Bridge 有等效功能。沒有已簽署 IPA。
- Camera Import artifact **1.1.0**／wire **1.0** 不變。此版沒有新增已存 Gallery JPEG 清單到 Serein 的離線交接，沒有 RAW 轉換、背景常駐、舊檔回灌、跨 session 去重或程序終止後續傳。
- 下載紀錄仍讀 schema 1／2、寫 schema 2，不保存可重新開啟的 Gallery URI，也不驗證檔案仍存在或來源 checksum；較早 schema-1-only 開發建置不保證無損降版。
- [v0.12.0 的限制](v0.12.0.md)仍適用：Close 不取消仍在載入的 display HTTP，USB 更廣泛的過期 storage 狀態發布尚未解決，完整 RAW 顯影、藍牙配對及跨平台功能一致性仍未完成。
- 沒有新增實體 EOS／手機／實際 Wi-Fi 驗收。R6 Mark III 大卡、弱網、其他機型／韌體、光學對焦與相機真實狀態仍需對應 device evidence；不能用 synthetic HTTP／emulator 通過替代。

## English

`0.13.0` adds explicit foreground JPEG delivery for the current Android direct-CCAPI connection. While the app remains foregrounded, newly observed JPEG originals can be saved to phone Gallery. This coherent user capability warrants a minor version. It remains a **Development Preview** for testing and feedback, unsuitable for production camera workflows.

### Use and scope

1. On Android 10+, connect directly with CCAPI and enable foreground saving from Gallery after reviewing the new-JPEG scope, destination, foreground requirement and cleanup notice.
2. Wait for two matching, complete bounded starting inventories. Existing files are excluded, with a 2000-item starting limit. Partial or oversized listings stop visibly.
3. Keep the app foregrounded. Newly observed JPEG candidates require two fresh positive sizes that remain equal at least one second apart. Each admitted original uses one GET into a MediaStore pending row and becomes public only after complete write, close and length validation. A new ID means newly observed, not proven capture by this connection or shutter action.
4. Watch queue/completion feedback or press Stop. Remembered IDs are capped at 4096 and the queue, including the active save, at 20. Partial/oversized listings cannot pass as complete. Stop, background and connection replacement cancel and await owned cleanup; returning or reconnecting requires explicit re-enabling.

Unconfirmed cleanup remains visible; acknowledging the notice does not delete a file. Finalized originals survive later cancellation or history-write failure. Failed automatic transfers do not retry originals or replay shutter, recording or focus commands. The original full control viewport is retained without an import status row; when present, system insets are consumed once, preserving held-AF, zoom and safe-area assertions.

### Upgrade and limitations

- Android is **0.13.0 / versionCode 29**, retaining the Preview package and development signer. In-place updates require the same package/signer; isolated `.debug` builds remain separate.
- iOS is **0.13.0 / build 27**, and Bridge/Simulator product versions match. Foreground import is Android direct CCAPI only; matching versions add no iOS/PC/USB/Bridge equivalent. No signed IPA is supplied.
- Camera Import artifact **1.1.0** / wire **1.0** is unchanged. This release adds no offline saved-Gallery-to-Serein list, RAW conversion, persistent background service, old-file backfill, cross-session deduplication or process-resumable transfer.
- Download history still reads schemas 1/2 and writes schema 2, without reopenable Gallery URIs, file-existence checks or source-checksum verification. Lossless downgrade to earlier schema-1-only development builds is not guaranteed.
- [v0.12.0 limitations](v0.12.0.md) remain: Close does not cancel pending display HTTP work; broader stale USB storage-state publication, full RAW development, Bluetooth pairing and platform parity remain unresolved.
- No new physical EOS/phone/Wi-Fi evidence is supplied. R6 Mark III large cards, weak networks, other models/firmware, optical focus and actual camera state require corresponding device evidence. Synthetic HTTP and emulator passes do not establish those claims.
