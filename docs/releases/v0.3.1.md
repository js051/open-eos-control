# Open EOS Control v0.3.1 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 的 `0.3.x` 修正版，集中改善 Android 使用者剛拍完照片後開啟相機媒體的等待時間。預設畫面現在優先取得最新 60 筆，而不是每次進入媒體庫都先遍歷數千個檔案；需要整理整張記憶卡時，仍可明確切換為完整載入。

### 最近媒體體驗

- Android 相機媒體預設載入最新 60 筆，並額外探測一筆以顯示記憶卡尚有更多內容。
- 「最近」與「整張記憶卡」是明確的載入範圍；部分結果不會冒充整張卡的總數。
- Direct CCAPI 與 Android USB/PTP 會在取得足夠的最近項目後停止列舉，避免不必要的完整遍歷。
- 相機事件公告的新素材會合併到最近清單，不必為了看到剛拍的照片立刻重掃整張卡。
- 缺少可靠拍攝時間時保留相機回傳順序，避免用猜測的日期重新排列檔案。

### 縮圖與狀態

- 同時最多處理兩個縮圖要求，降低相機 Wi-Fi 被大量請求塞滿的機會。
- 暫時性的縮圖 I/O 失敗會自動重試一次；永久失敗仍保留可理解的佔位狀態。
- 最近／完整範圍、載入狀態及診斷欄位均提供英文與繁體中文資源。

### 下載與限制

- `open-eos-control-android-0.3.1-debug.apk` 使用既有固定開發簽章，可從 v0.1.5 之後的同簽章預覽版覆蓋安裝。
- 本次仍產出 Windows x64 Desktop Bridge、Bridge Python 套件、發行說明與 SHA-256 校驗值，確保多平台版本一致。
- 經 Desktop Bridge 使用媒體庫時，Android 雖只顯示最近範圍，Bridge 端在本版仍可能先列舉完整清單；端到端有界列舉將在後續版本完成。
- 本版未加入可安裝的 iOS IPA。實體相機上的大型記憶卡耗時、影片 codec 相容性與 USB/PTP 行為仍需持續驗證。

## English

This `0.3.x` patch focuses on the Android workflow immediately after taking photos. Camera Media now requests the newest 60 items first instead of traversing thousands of files every time the library opens. A deliberate full-card mode remains available for complete card management.

### Recent Media Workflow

- Android loads the newest 60 camera-media items by default and probes one additional item to indicate that more content exists.
- Recent and full-card loads are explicit scopes; a partial result is never presented as the total card count.
- Direct CCAPI and Android USB/PTP stop enumeration after enough recent items are available, avoiding unnecessary full traversal.
- Newly announced camera events merge into the recent list so a just-captured photo can appear without an immediate full rescan.
- Camera order is retained when reliable capture timestamps are unavailable instead of inventing a date-based order.

### Thumbnails And Status

- At most two thumbnail requests run concurrently to reduce pressure on camera Wi-Fi.
- Transient thumbnail I/O failures retry once; permanent failures retain a clear placeholder state.
- Load scope, status, and diagnostics have English and Traditional Chinese resources.

### Downloads And Limitations

- `open-eos-control-android-0.3.1-debug.apk` uses the existing stable development signer and can update matching previews from v0.1.5 onward.
- The release still produces the Windows x64 Desktop Bridge, Bridge Python packages, release notes, and SHA-256 checksums so platform versions remain aligned.
- For Android connections through Desktop Bridge, the UI is recent-scoped but this release may still enumerate the complete list inside the Bridge before truncation. End-to-end bounded Bridge enumeration remains follow-up work.
- No installable iOS IPA is included. Large-card latency, video-codec compatibility, and USB/PTP behavior still need continued physical-camera validation.
