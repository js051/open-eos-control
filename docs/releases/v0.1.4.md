# Open EOS Control v0.1.4 Development Preview

[繁體中文](#繁體中文) | [English](#english)

## 繁體中文

這是 Open EOS Control 的第五個開發預覽版。本版重點是 Android 相機式方向操作，並將亮度波形圖與 3D `.cube` LUT 預覽帶到 Android、iOS 與 PC。真機驗證仍以 Canon EOS R6 Mark III 為優先；此版本仍是測試用途，不應視為正式拍攝工具。

### 下載

- `open-eos-control-android-0.1.4-debug.apk`：可側載的 Android debug 版本，以 Android SDK debug 憑證簽署。
- `open-eos-control-bridge-windows-x64-0.1.4.exe`：包含 Python runtime、PyAV／FFmpeg 與控制介面的 Windows x64 單檔 Desktop Bridge。
- `open_eos_control_bridge-0.1.4-py3-none-any.whl`：跨平台 Desktop Bridge Python wheel。
- `open_eos_control_bridge-0.1.4.tar.gz`：Desktop Bridge 原始碼套件。
- `SHA256SUMS.txt`：所有附件的 SHA-256 校驗值。

Android APK 與 Windows 執行檔並非正式簽章。Windows USB 控制仍需系統提供 `gphoto2`／libgphoto2。iOS 仍只提供原始碼，實體裝置版本需使用 Xcode 建置與簽署。

### 重點更新

- Android 保持 Live View、曝光列與快門的整體位置，只旋轉固定尺寸內的圖示、數值與狀態。
- 控制方向會讀取 Android 系統自動旋轉開關；關閉時忽略感測器姿態，重新開啟後也不會沿用鎖定期間的舊樣本。
- 橫握時使用緊湊的 HUD 內容與有界的警告面板，避免繁中長文字與放大字體跑版。
- Android、iOS 與 PC 新增亮度波形圖，並與 histogram 保持互斥，避免監看畫面同時堆疊。
- Android、iOS 與 PC 可在記憶體中匯入有界的 3D `.cube` LUT；原生 RTP 零複製路徑仍明確停用像素 LUT，不偽裝支援。
- `main` CI 成功後會保留七天 Android debug APK，方便在正式 tag 前進行 R6 Mark III 真機驗證。

### 已知限制

- 並非所有功能都已在 EOS R6 Mark III 完成完整真機回歸；未由相機或 backend 公告的能力不會顯示可操作控制。
- Android 方向行為已在 Pixel API 34 AVD 驗證；實體 Pixel 仍需以此版安裝後確認旋轉鎖定與各字體大小。
- Canon CCAPI RTP 目前只處理 H.264 影像，不含 AAC LATM 音訊。
- 此 release 不提供已簽署的 iOS IPA。

## English

This is the fifth Open EOS Control development preview. It focuses on Android camera-style orientation behavior and brings luminance waveform and 3D `.cube` LUT preview to Android, iOS, and PC. Physical validation still prioritizes the Canon EOS R6 Mark III; this remains a test build and should not be treated as a production capture tool.

### Downloads

- `open-eos-control-android-0.1.4-debug.apk`: sideloadable Android debug build signed with the Android SDK debug certificate.
- `open-eos-control-bridge-windows-x64-0.1.4.exe`: single-file Windows x64 Desktop Bridge containing the Python runtime, PyAV/FFmpeg, and control UI.
- `open_eos_control_bridge-0.1.4-py3-none-any.whl`: cross-platform Desktop Bridge Python wheel.
- `open_eos_control_bridge-0.1.4.tar.gz`: Desktop Bridge source distribution.
- `SHA256SUMS.txt`: SHA-256 checksums for all attached files.

The Android APK and Windows executable are development-signed. Windows USB control still requires system-provided `gphoto2`/libgphoto2. iOS remains source-only; physical-device builds must be built and signed with Xcode.

### Highlights

- Android keeps the overall Live View, exposure strip, and shutter positions fixed while rotating only icons, values, and status inside stable bounds.
- Control orientation reads the Android system auto-rotate setting. Rotation lock ignores sensor posture, and unlocking does not reuse a stale sample captured while locked.
- Quarter turns use compact HUD content and bounded notice panels so Traditional Chinese and enlarged text do not escape their layout.
- Android, iOS, and PC add a mutually exclusive luminance waveform alongside the existing histogram.
- Android, iOS, and PC can import a bounded in-memory 3D `.cube` LUT. Native zero-copy RTP paths explicitly keep pixel LUT processing disabled instead of claiming unsupported behavior.
- Successful `main` CI runs retain an Android debug APK for seven days, enabling R6 Mark III validation before the next tagged release.

### Known Limitations

- Not every feature has completed a full physical regression pass on the EOS R6 Mark III. Controls remain gated by camera/backend advertisement.
- Android orientation behavior is verified on a Pixel API 34 AVD; the physical Pixel still needs this build installed to confirm rotation lock and enlarged text.
- Canon CCAPI RTP currently handles H.264 video only, without AAC LATM audio.
- This release does not include a signed iOS IPA.
