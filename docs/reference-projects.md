# Reference Projects And Validity Map

This project should stay grounded in public specifications, official platform APIs, and working open-source camera-control projects. Features must be marked as implemented only when the code path exists in this repo and has passed local tests.

## Primary References

- Canon CCAPI: Canon documents CCAPI as an HTTP-based API for controlling Canon cameras over a network, usable from a smartphone, tablet, or computer. Reference: [Canon CCAPI product manual](https://cam.start.canon/en/C017/manual/html/UG-06_Network_0130.html).
- Canon CAP release status: Canon's public release notes list CameraControlAPI Reference v1.4.0 Rev.1.4 as of March 31, 2026. Canon's public Camera API page lists deletion of images on storage media as a CCAPI/EDSDK capability; the API specification and official Android sample distributed through CAP remain the conformance source for endpoint payloads. References: [Canon Camera API Package](https://asia.canon/en/campaign/developerresources/cap), [Canon CAP overview](https://asia.canon/en/campaign/developerresources/camera/cap/cap), [CCAPI release notes](https://asia.canon/en/campaign/developerresources/camera/cap/camera-control-api-release-note).
- Canon CCAPI manual focus: a pinned public mirror of Canon's Android CCAPI 1.3 sample sends `POST /shooting/control/drivefocus` with a `value` string selected from `near1` through `near3` or `far1` through `far3`. Open EOS Control follows that request contract only when the camera advertises the POST operation. References: [Canon sample request builder](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/WebAPI.java), [Canon sample control UI](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/RemoteCaptureFragment.java).
- Canon CCAPI autofocus: the same pinned Canon Android sample sends `POST /shooting/control/af` with `{"action":"start"}` and `{"action":"stop"}`. Open EOS Control exposes `AUTOFOCUS` only when that POST or a verified balanced half-press path is available, and always attempts the matching stop/release. References: [Canon sample request builder](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/WebAPI.java), [Canon sample remote capture flow](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/RemoteCaptureFragment.java).
- Canon CCAPI coordinate Tap AF: the pinned Canon Android sample reads `image.positionx`, `positiony`, `positionwidth`, and `positionheight` from `flipdetail?kind=both`, maps the displayed-image touch into that camera coordinate space, and sends `PUT /shooting/liveview/afframeposition` with integer `positionx` and `positiony`. Open EOS Control implements this exact bounded packet/metadata flow on Android, iOS, and the PC CCAPI engine; it never sends guessed normalized coordinates. References: [Canon sample request builder](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/WebAPI.java), [touch-coordinate mapping](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/RemoteCaptureFragment.java), [detailed Live View parser](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/OrgFormatDataSet.java).
- Canon CCAPI Click White Balance: the same pinned Canon sample maps the displayed-image touch through detailed Live View geometry and sends `POST /shooting/liveview/clickwb` with integer `positionx` and `positiony`. Open EOS Control uses that exact capability-gated contract on Android, iOS, and the PC CCAPI engine; USB/PTP and libgphoto2 do not expose it without separate verified command evidence. References: [Canon sample request builder](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/WebAPI.java), [Canon sample remote-capture UI](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/RemoteCaptureFragment.java).
- Canon CCAPI RTP Live View: Canon's CCAPI 1.3 API Reference sections 4.11.7, 4.11.8 and 6.2.23 define `GET rtpsessiondesc`, `POST rtp` with `action`/`ipaddress`, H.264/90 kHz video on the SDP video port, and AAC LATM/48 kHz audio. The pinned Canon Android sample writes the returned SDP, starts distribution to the client's Wi-Fi address, and opens the SDP in a video player. Open EOS Control implements RFC 3550 packet parsing and RFC 6184 H.264 depacketization on Android, iOS, and PC. Android renders through `MediaCodec`; iOS uses Wi-Fi-only Network.framework listeners and `AVSampleBufferVideoRenderer`; PC binds the routed local IPv4/UDP port, decodes with PyAV/FFmpeg, and converts selected decoded frames to JPEG for the stable Bridge API. Audio remains unsupported. References: [pinned CCAPI 1.3 API Reference mirror](https://github.com/laxei-app/HolyGrailController/blob/85ffbb93415d82513cb6a3c20ddd7073b9fd169e/30_refer/20_manual/API%20canon/ccapi-1.3.0d/Document/CameraControlAPI_Reference_v130_EN.pdf), [Canon sample request builder](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/WebAPI.java), [Canon sample RTP lifecycle](https://github.com/Chieri-JN/Intervelo/blob/bb826a1211c49a6d3a569ec8c4b9934b585db270/CCAPI_Sample_Android_1.3.0e/Sample/app/src/main/java/com/canon/ccapisample/RemoteCaptureFragment.java), [RFC 3550](https://www.rfc-editor.org/rfc/rfc3550), [RFC 6184](https://www.rfc-editor.org/rfc/rfc6184), [Android MediaCodec](https://developer.android.com/reference/android/media/MediaCodec), [Apple Network.framework](https://developer.apple.com/documentation/network), [Apple sample-buffer renderer](https://developer.apple.com/documentation/avfoundation/avsamplebuffervideorenderer), [PyAV codec parsing example](https://pyav.org/docs/stable/cookbook/basics.html#parsing), [PyAV frame conversion](https://pyav.org/docs/stable/api/video.html#av.video.frame.VideoFrame.to_image).
- Public CCAPI discovery capture: a pinned open-source Canon wrapper reads the camera origin directly and records a real EOS R100 `/ccapi` response whose version arrays contain full same-origin `url` values plus `get`/`post`/`put`/`delete` flags. Open EOS Control uses this only as reproducible evidence for the discovery response shape; it does not substitute for R6 Mark III validation. References: [root discovery request](https://github.com/qwasium/ugoku-kun/blob/aaab560fbf1921c5fa0035d34dc68f041e704a52/src/ugokukun/cannon_wrapper.py), [pinned camera dump](https://github.com/qwasium/ugoku-kun/blob/aaab560fbf1921c5fa0035d34dc68f041e704a52/readme_demo/dump/camera_0.json).
- Android USB host: Android documents `UsbManager`, `UsbDevice`, `UsbInterface`, `UsbEndpoint`, explicit permission requests, and endpoint communication. Reference: [Android USB host overview](https://developer.android.com/develop/connectivity/usb/host).
- PTP: PTP is ISO 15740:2013 and is defined as a transport- and platform-independent protocol for digital still photography devices. Reference: [ISO 15740:2013](https://www.iso.org/standard/63602.html).
- USB still image class: USB-IF publishes the Still Image Capture Device Class specification used by USB PTP devices. Reference: [USB-IF Still Image Capture Device Definition](https://www.usb.org/document-library/still-image-capture-device-definition-10-and-errata-16-mar-2007).
- libgphoto2 / gPhoto: libgphoto2 is the main open-source reference for camera access/control and PTP-backed Canon EOS tethering. Its CLI manual defines `--get-thumbnail RANGE or NAME`; Open EOS Control uses that exact folder/name command only when `gphoto2 --abilities` reports file-preview support. Reference: [libgphoto2 GitHub](https://github.com/gphoto/libgphoto2), [gPhoto CLI manual](https://www.gphoto.org/doc/manual/ref-gphoto2-cli.html), [gPhoto remote control docs](https://gphoto.sourceforge.io/doc/remote/), [supported cameras](https://gphoto.sourceforge.io/proj/libgphoto2/support.php).
- EOS R6 Mark III libgphoto2 evidence: upstream includes a generated R6 Mark III configuration snapshot with Canon EOS capture abilities, storage, battery, shooting mode, exposure, color temperature, WB shifts, color space, aspect ratio, power-zoom speed, High ISO noise reduction, AEB, remote release, movie target, and manual focus-drive values. It is concrete adapter evidence, but it does not replace this project's physical-device acceptance record. Reference: [pinned R6 Mark III snapshot](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/cameras/canon-eos-r6-markIII.txt), [gphoto2 CLI manual](https://www.gphoto.org/doc/manual/ref-gphoto2-cli.html).
- Canon EOS PTP behavior reference: pinned libgphoto2 source defines the remote/event operations, property-event layouts and value tables, balanced release sequence, `DriveLens` values, movie target, EVF properties, `GetViewFinderData` request and block format mirrored by the Android backend. References: [operation/property definitions](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/ptp.h), [Canon property packet writer](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/ptp.c), [Canon event parser](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/ptp-pack.c), [capture and Live View behavior](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/library.c), [settings, focus and remote controls](https://github.com/gphoto/libgphoto2/blob/ce6c5f7c7fdde404e9897f618df6168c01df70f5/camlibs/ptp2/config.c).
- Canon EOS R6 Mark III Traditional Chinese terminology: display-only shooting-mode, AF, metering and Picture Style translations follow Canon's official Taiwan manual; backend writes continue to use the camera-advertised raw values. References: [shooting modes](https://cam.start.canon/tc/C022/manual/html/UG-02_ShootingStill_0010.html), [AF operation](https://cam.start.canon/tc/C022/manual/html/UG-05_AF-Drive_0040.html), [AF area](https://cam.start.canon/tc/C022/manual/html/UG-05_AF-Drive_0060.html), [metering mode](https://cam.start.canon/tc/C022/manual/html/UG-04_Shooting_0230.html), [Picture Style](https://cam.start.canon/tc/C022/manual/html/UG-04_Shooting_0260.html).

## Open-Source Behavior To Mirror

- Capability-driven UI: libgphoto2 exposes configuration and capture support per camera model, so Open EOS Control must expose backend capabilities instead of assuming every camera/transport supports every command.
- EOS USB control path: gPhoto lists many Canon EOS R bodies, including EOS R6 and R6 Mark II, with image capture, trigger capture, liveview, and configuration support. R6 Mark III still needs direct validation, so it remains this project's golden test target rather than a claimed upstream-supported body.
- Desktop bridge path: the PC bridge should follow the libgphoto2 model first. Canon EDSDK can be an optional local adapter, but proprietary SDK binaries must not be committed or redistributed here.

## Current Validity Map

Implemented and test-covered:

- CCAPI network backend shape, same-origin canonical `url` and relative `path` discovery parsing, simulator contract, dynamic settings, recording, Canon `afframeposition` Tap AF and `clickwb` Click White Balance backed by detailed Live View geometry, advertised `drivefocus` Near/Far control, JPEG live view polling, Android/iOS/PC RTP H.264 video, still/manual shutter control, paged media browsing, streaming media download, and deletion gated by an advertised `DELETE` operation.
- Android USB host diagnostics: enumerate devices, identify Canon vendor ID `0x04A9`, identify PTP still-image interfaces, show endpoints, and request Android USB permission.
- Android standards-based USB/PTP path: claim the interface, open/close a session, parse DeviceInfo, property, storage and object datasets, safely write bounded camera-advertised standard properties, conditionally issue advertised standard still capture, browse media, retrieve bounded embedded thumbnails with standard `GetThumb (0x100A)`, stream `GetObject` downloads, and issue exact-handle `DeleteObject` only when advertised.
- Android Canon EOS USB path: capability-gated remote/event setup, shooting mode, ISO/Tv/Av/WB, exposure compensation, color temperature, signed WB shifts, color space, aspect ratio, power-zoom speed, High ISO noise reduction and AEB event state/writes, still capture with balanced release and event confirmation, timed half-press, Card/None movie control, Near/Far focus drive, EVF start/stop, and in-memory JPEG Live View parsing.
- Desktop Bridge service, libgphoto2 CLI adapter, direct PC CCAPI engine, and Android/iOS bridge clients: authenticated sessions, dynamic settings/capabilities, capture, focus, JPEG preview, advertised RTP receive/decode on PC, capability-gated media thumbnails, media streaming/deletion and deterministic contract tests. The pinned R6 Mark III snapshot reports file download/deletion capabilities; thumbnail retrieval remains gated by the runtime `gphoto2 --abilities` file-preview result, and the gPhoto2 CLI manual defines the exact folder/name thumbnail and deletion commands.
- Multi-backend contract: unsupported operations throw explicit transport/feature errors.

Implemented but requires real-camera verification:

- Real Canon CCAPI endpoint variants for R6 Mark III live view and shooting settings.
- R6 Mark III still/manual shutter, recording, tap focus, Click White Balance, CCAPI manual focus drive, media browsing, PTP/libgphoto2 media thumbnails, media download, and media deletion.
- Android USB/PTP diagnostics, session, DeviceInfo, standard properties, storage/media, download, advertised standard capture, and the implemented Canon remote/exposure/movie/focus/Live View paths on a physical Android device with the camera connected over OTG/USB-C.
- PC direct CCAPI JPEG/RTP, Desktop Bridge USB, and Android bridge client with a physical R6 Mark III.
- iOS CCAPI app with a physical iPhone and R6 Mark III.

Recorded physical evidence:

- [Sanitized Android/R6 Mark III CCAPI validation](validation/eos-r6-mark-iii-android-ccapi.md): discovery, identity, battery, advertised exposure controls, the Live View parameter fallback, and requested/observed 15 FPS are recorded; shutter, movie, Tap AF, Click White Balance, media, Wi-Fi/cellular coexistence, and USB remain explicitly pending.

Planned only, not product-valid yet:

- Canon EOS USB Touch AF and remaining vendor settings beyond the implemented shooting-mode, exposure, color, aspect-ratio, power-zoom, image-quality, AF, drive, metering and movie mappings.
- Android/iOS/PC AAC LATM audio.
- Optional EDSDK adapter.

## Development Rule

Do not mark a feature as supported unless both conditions are true:

1. The repo contains an executable code path for that feature.
2. The feature is covered by automated tests, simulator tests, or a recorded real-device validation note.

Otherwise expose it as `planned`, `research`, or `unsupported`.
